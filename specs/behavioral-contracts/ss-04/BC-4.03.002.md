# BC-4.03.002: Every Provenance Sidecar Has a Valid `disclosure_class` (One of Three Exact Values)

## Description

The `disclosure_class` field on every ProvenanceSidecar must be one of exactly three values:
`pre-generated`, `live-generated`, or `procedural-exempt`. This field is the primary data
source for the `ai-disclosure-manifest` (CAP-010) and for EU AI Act Art. 50 C2PA machine-
readable marks. A missing, null, empty, or out-of-vocabulary `disclosure_class` is a schema
error that prevents the asset from being ingested. This BC defines the computation logic for
`disclosure_class` and its validation rule.

## Preconditions

1. A GenerationRequest has been processed by a backend adapter (or a procedural generator).
2. The provenance sidecar is being constructed per BC-4.03.001.
3. The factory knows the generation method (neural model vs classical procedural algorithm).

## Behavior

1. During sidecar construction (BC-4.03.001 step 1), the orchestrator determines
   `disclosure_class` using the following decision tree:
   a. **Procedural check first:** If the generation `modality` field on the request is
      `procedural` AND the adapter declares `training_data_provenance: none` (no ML model):
      - `disclosure_class = "procedural-exempt"`
   b. **Live-generation check:** If the request field `generation_timing` is
      `runtime` (content is generated on-the-fly during gameplay by a model):
      - `disclosure_class = "live-generated"`
   c. **Default (all other neural/ML generation):** All AI generative-model output that
      ships with the product (generated ahead of runtime):
      - `disclosure_class = "pre-generated"`
2. The schema validator then checks that `disclosure_class` is one of
   `{pre-generated, live-generated, procedural-exempt}` exactly (case-sensitive).
3. **Happy path:** `disclosure_class` is one of the three valid values.
   - Sidecar field is written; construction continues.
4. **Failure path A:** `disclosure_class` is null or absent.
   - Error `E-PRV-010` ("disclosure_class is required; null or absent value detected").
5. **Failure path B:** `disclosure_class` is a value outside the allowed set
   (e.g., `"ai-generated"`, `"generated"`, `"procedural"` — all incorrect).
   - Error `E-PRV-011` ("disclosure_class '<value>' is not in allowed set").
6. **Special rule for `procedural-exempt`:** If `disclosure_class` is set to
   `"procedural-exempt"` but the adapter used a neural model (i.e., the adapter's
   `training_data_provenance != "none"`), this is treated as an error:
   - Error `E-PRV-012` ("disclosure_class 'procedural-exempt' is invalid for neural-model
     adapter '<id>'; only classical procedural generation qualifies").

## Postconditions

- The provenance sidecar has `disclosure_class` set to exactly one of
  `{pre-generated, live-generated, procedural-exempt}`.
- The assignment logic used is recorded in the sidecar's audit metadata.
- Every asset with `disclosure_class: live-generated` is additionally flagged for developer
  attestation (the developer must attest the live-generation system will not produce
  illegal/prohibited content — per Steam Jan 2026 policy).

## Invariants

- `procedural-exempt` may ONLY be assigned to assets generated by non-ML classical
  algorithms (WFC, BSP, Perlin noise, SpeedTree, Houdini PDG without neural operators).
- `live-generated` is reserved for content generated at runtime by a neural model during
  active gameplay. Pre-calculated content (even if generated seconds before use) is
  `pre-generated`.
- The three-value enum is closed; no additional values may be introduced without a schema
  version bump and a corresponding policy update (minimum: ADR filed, CAP-010 updated).
