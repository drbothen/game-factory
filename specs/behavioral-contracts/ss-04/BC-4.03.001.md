# BC-4.03.001: Every Generated Asset Has a Complete Provenance Sidecar Populated at Generation Time (DI-003)

## Description

This is the primary enforcement BC for domain invariant DI-003. Every asset generated by
the factory pipeline must have a provenance sidecar with ALL required fields populated
at the moment of generation, before the asset is returned to the orchestrator. The sidecar
must be created as an atomic unit with the asset — it is not an optional post-processing
step. An asset without a complete sidecar MUST NOT proceed to the quality gate or be
ingested into the asset store.

The sidecar is the source of truth for all downstream compliance operations: the
`ai-disclosure-manifest` (CAP-010), the ship-gate license check (BC-4.05.001), and the
human-gated consent gate (BC-4.03.004).

## Preconditions

1. A GenerationRequest has been validated (BC-4.02.001) and risk tier has been assigned
   (BC-4.02.002).
2. A backend adapter has been selected (BC-4.01.002).
3. The backend adapter has completed raw asset generation.
4. The factory has the generation context (tool identity, model version, prompt log,
   generation timestamp, license terms for the selected adapter) available.

## Behavior

1. At generation completion, the asset-generation orchestrator constructs the
   `ProvenanceSidecar` document from the generation context. All fields are populated
   from authoritative sources — nothing is inferred or approximated:
   - `generated_by_tool.name`: from the adapter's registered `name` field
   - `generated_by_tool.vendor`: from the adapter's registered `vendor` field
   - `generated_by_tool.model_version`: from the adapter's generation response; if the
     adapter does not expose model version, write `"backend-opaque"` (never `"unknown"`)
   - `generation_date`: UTC ISO 8601 timestamp of generation completion
   - `prompt_and_inputs_log`: the full prompt and all reference inputs, verbatim; never
     truncated (truncation requires re-generation with a longer log)
   - `human_modifications_log`: empty list `[]` at generation (populated only if a human
     later transforms the asset)
   - `license_terms_snapshot.commercial_use`: from adapter's registered license record
   - `license_terms_snapshot.resale_allowed`: from adapter's registered license record
   - `license_terms_snapshot.attribution_required`: from adapter's registered license record
   - `license_terms_snapshot.indemnification_tier`: from adapter's registered license record
   - `training_data_provenance`: from adapter's registered training provenance field
   - `likeness_consent_ref`: null unless the request carried a `likeness_ref`
   - `risk_tier`: copied from the request's immutable `risk_tier` field
   - `copyrightability_assessment`: computed by BC-4.03.003
   - `disclosure_class`: computed by BC-4.03.002
2. The orchestrator validates the sidecar against the canonical schema
   (`provenance-sidecar.schema.json`).
3. **Happy path:** All fields are present, non-null (except `likeness_consent_ref` which
   may be null for non-likeness assets), and schema-valid.
   - Sidecar is attached to the asset as an inseparable unit.
   - The (asset, sidecar) pair is passed to the quality gate.
4. **Failure path A:** One or more required sidecar fields are missing or null.
   - Error `E-PRV-001` ("provenance sidecar incomplete: missing fields [list]").
   - The asset is NOT passed to the quality gate.
   - The request moves to `status: sidecar_error`.
   - The asset-generation orchestrator retries generation with an explicit prompt to the
     adapter to expose model version. On second failure, the request moves to
     `status: blocked` and the producer is notified.
5. **Failure path B:** `prompt_and_inputs_log` is truncated (detected by comparing
   against the original request's `prompt_inputs` — if log is shorter than 80% of
   original input length, flag as truncated).
   - Error `E-PRV-002` ("provenance prompt log appears truncated; re-generation required").
   - Re-generate with an explicit instruction to the adapter to return the full prompt log.
6. **Failure path C:** `generated_by_tool.model_version` is `"unknown"`.
   - Error `E-PRV-003` ("model_version 'unknown' is not a valid provenance value; use
     'backend-opaque' if the adapter does not expose version").
   - The sidecar is rejected; adapter must be updated.

## Postconditions

- **Complete sidecar:** The asset has an inseparable `ProvenanceSidecar` with all required
  fields non-null (except allowed nullable `likeness_consent_ref`) and schema-valid.
- **Incomplete sidecar:** The asset is in `status: sidecar_error` or `status: blocked`.
  The asset-store ingest hook will refuse to accept it (BC-4.06.001).
- Every sidecar creation event is recorded in the provenance log with the asset_id and
  a checksum of the sidecar document.

## Invariants

- The sidecar is created at generation time; it cannot be retrofitted after the fact for
  a shipped asset. A post-hoc sidecar is only valid for non-ship use (review/audit).
- `generated_by_tool.model_version: "unknown"` is explicitly invalid and rejected.
- `prompt_and_inputs_log` is never omitted, never replaced with a summary.
- The (asset, sidecar) pair is immutable; the asset's file content may not be changed
  without resetting `human_modifications_log` and potentially triggering re-assessment.

## Edge Cases

| EC-ID | Scenario | Expected Result |
|-------|----------|----------------|
| EC-001 | Adapter API response does not include model version | Write `"backend-opaque"` for `model_version`; copyrightability_assessment set to `unlikely` per BC-4.03.003 |
| EC-002 | Asset is procedurally generated (WFC, Perlin) — no neural model involved | `disclosure_class: procedural-exempt`; `generated_by_tool` records the PCG algorithm name as `name`; `model_version: "n/a-procedural"` |
| EC-003 | Adapter crashes mid-generation; partial asset exists but sidecar was never created | Treat as sidecar_error; discard partial asset; retry full generation |
| EC-004 | A human transforms the asset post-generation (retopology, UV fix) | `human_modifications_log` is updated with the transformation record; `copyrightability_assessment` may be re-assessed (improves from `unlikely` toward `partial` or `likely`) |
| EC-005 | Two assets generated from the same prompt with different seeds | Each asset gets its own sidecar; `request_id` differs; `generation_date` differs |
| EC-006 | Adapter returns the same model_version for all assets regardless of actual version | Accepted as-is; the factory records what the adapter reports; vendor accuracy is the adapter's responsibility |

## Canonical Test Vectors

| Scenario | Expected |
|----------|---------|
| Full generation with cloud-api adapter that exposes model version | Complete sidecar, all fields populated, `status: ok` |
| Adapter returns `model_version: "unknown"` | E-PRV-003, sidecar rejected |
| Prompt log returned is empty string | E-PRV-002 (truncation detected) |
| Procedural terrain (WFC algorithm) | Sidecar with `disclosure_class: procedural-exempt`, `model_version: "n/a-procedural"` |
| Voice asset with `likeness_ref` set | Sidecar with `likeness_consent_ref: "<id>"`, triggers BC-4.03.004 |
| Adapter crash mid-generation | Asset discarded, sidecar_error, retry |

## Verification Properties

- **VP-4.03.001-a:** `∀ asset a ∈ asset_store: a.sidecar is present ∧ a.sidecar.schema_valid = true`
- **VP-4.03.001-b:** `∀ asset a ∈ asset_store: a.sidecar.generated_by_tool.model_version ≠ "unknown"`
- **VP-4.03.001-c:** `∀ asset a ∈ asset_store: a.sidecar.prompt_and_inputs_log ≠ null ∧ a.sidecar.prompt_and_inputs_log ≠ ""`
- **VP-4.03.001-d:** `∀ asset a ∈ asset_store: a.sidecar.generation_date is valid ISO 8601 UTC`
