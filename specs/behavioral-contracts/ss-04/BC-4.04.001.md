# BC-4.04.001: A Generated 3D Mesh Passes the Quality Gate Only When Manifold, Within Budget, UV-Valid, Full PBR, and Provenance Complete

## Description

The quality gate for 3D mesh assets verifies five independently checkable conditions.
All five must pass for the asset to receive `quality_gate_status: pass`. A failing condition
causes the asset to receive `quality_gate_status: fail` with a structured report enumerating
which checks failed and, for Tier-1 assets, triggers a re-generation attempt. For Tier-2/3
assets, a quality gate fail is recorded but the asset is still ingested per the pure-maximal
policy (D-006) — the fail record travels with the asset in the sidecar.

## Preconditions

1. A 3D mesh asset has been generated by a backend adapter (modality: text_to_3d or image_to_3d).
2. The raw asset binary (GLB or equivalent) is available for analysis.
3. A provenance sidecar has been constructed and attached (BC-4.03.001).
4. The quality-gate harness has access to mesh analysis tools (topology checker, UV analyzer,
   PBR channel validator).

## Behavior

Quality gate check 1 — **Manifold Geometry:**
- All mesh surfaces must be 2-manifold (every edge shared by exactly 1 or 2 faces).
- Zero non-manifold edges; zero non-manifold vertices.
- Zero isolated vertices.
- **Pass:** manifold_check = true.
- **Fail:** manifold_check = false; error E-QG-001 with non-manifold edge/vertex count.

Quality gate check 2 — **Polycount Within Budget:**
- Face count ≤ `request.budget.polycount_max`.
- Vertex count ≤ `request.budget.vertex_max` if specified.
- **Pass:** polycount_check = true.
- **Fail:** polycount_check = false; error E-QG-002 ("face count <actual> exceeds budget <max>").

Quality gate check 3 — **UV Distortion Within Threshold:**
- UV distortion (stretching, compression) ≤ 0.3 normalized distortion score (scale-independent).
- UV coverage ≥ 0.7 (≥ 70% of UV space utilized; no large wasted areas for the declared LOD).
- Zero UV seams that produce visible hard edges under PBR render (detected via normal-continuity
  proxy check).
- **Pass:** uv_check = true.
- **Fail:** uv_check = false; error E-QG-003 with distortion score and UV coverage ratio.

Quality gate check 4 — **Full PBR Channel Set Present:**
- For GLB output: at minimum albedo (base_color), metalness, roughness, and normal map must be
  present and non-zero in at least one UV region.
- Each texture channel must be at the declared `budget.texture_res` or higher.
- **Pass:** pbr_check = true.
- **Fail:** pbr_check = false; error E-QG-004 ("PBR channels missing: [list]").

Quality gate check 5 — **Provenance Complete:**
- The attached sidecar has no schema errors (BC-4.03.001 passed).
- `disclosure_class` is present and valid (BC-4.03.002 passed).
- `copyrightability_assessment` is present (BC-4.03.003 passed).
- **Pass:** provenance_check = true.
- **Fail:** provenance_check = false; error E-QG-005.

**Aggregation:**
- **All 5 pass:** `quality_gate_status: pass`.
  - Tier-1: auto-ingest to asset store (BC-4.06.001).
  - Tier-2/3: flag for record; ingest anyway.
- **Any check fails:**
  - Tier-1: `quality_gate_status: fail`; trigger re-generation (up to 2 retries with adjusted
    generation parameters); if still failing after 2 retries, move to `status: quality_blocked`,
    emit quality-gate-report, notify producer.
  - Tier-2/3: `quality_gate_status: fail`; ingest anyway with fail record; emit quality-gate-report
    advisory. Asset is marked `quality_flagged: true` in the asset store.

## Postconditions

- A `quality-gate-report` artifact is produced for every asset, whether pass or fail.
  The report includes the per-check result, the actual vs threshold values, and the final status.
- The `quality_gate_status` field is written to the asset store entry alongside the sidecar.
- Tier-1 assets with `quality_gate_status: fail` after retries are in `status: quality_blocked`
  and are NOT auto-ingested.

## Invariants

- The quality gate cannot be skipped; it runs on every 3D mesh asset.
- The quality gate for Tier-2/3 assets does NOT block ingest (pure-maximal); the fail is
  a data record, not a gate.
- Re-generation retries use the original `request_id`; each retry creates a new sub-request
  with a retry count suffix.
- The quality-gate thresholds (manifold, UV distortion ≤ 0.3, UV coverage ≥ 0.7, polycount
  ≤ budget) are constants; they are not configurable per-project.

## Edge Cases

| EC-ID | Scenario | Expected Result |
|-------|----------|----------------|
| EC-001 | Mesh is manifold but UV coverage is 0.45 (below 0.7 threshold) | uv_check fails; Tier-1 → retry; Tier-2/3 → ingest with advisory |
| EC-002 | PBR set has albedo and normal but no metalness/roughness | pbr_check fails (metalness and roughness are required channels) |
| EC-003 | Mesh passes all geometry checks but sidecar is missing `disclosure_class` | provenance_check fails; E-QG-005; even Tier-1 with otherwise-passing geometry is blocked |
| EC-004 | Tier-3 hero character fails manifold and UV checks | Ingest with `quality_flagged: true`, both failures in quality-gate-report, advisory to producer |
| EC-005 | Retry 1 passes manifold but still fails UV; retry 2 passes all checks | quality_gate_status: pass on retry 2; retry_count: 2 recorded in quality-gate-report |
| EC-006 | Mesh has quad topology (from Rodin Gen-2.5 quad mode) — does this affect checks? | No difference; manifold and UV checks apply equally to quad and triangle meshes |

## Canonical Test Vectors

| Mesh scenario | Expected quality_gate_status | Tier-1 outcome | Tier-2/3 outcome |
|--------------|------------------------------|---------------|-----------------|
| All 5 checks pass | `pass` | Auto-ingest | Ingest |
| Non-manifold mesh, all others pass | `fail` (E-QG-001) | Retry then quality_blocked | Ingest with flag |
| Polycount 150k, budget 100k | `fail` (E-QG-002) | Retry then quality_blocked | Ingest with flag |
| UV coverage 0.55 | `fail` (E-QG-003) | Retry then quality_blocked | Ingest with flag |
| Missing roughness channel | `fail` (E-QG-004) | Retry then quality_blocked | Ingest with flag |
| Valid mesh but `disclosure_class` null | `fail` (E-QG-005) | Blocked (provenance is always hard gate) | Blocked (provenance is always hard gate, even Tier-2/3) |

Note on the last test vector: provenance completeness failure is a hard gate for ALL tiers,
because a missing `disclosure_class` violates DI-003 and blocks the `ai-disclosure-manifest`.

## Verification Properties

- **VP-4.04.001-a:** `∀ asset a ∈ asset_store: a.quality_gate_report is present`

- **VP-4.04.001-d:** `∀ Tier-1 3D mesh a in asset_store: a.mesh.is_manifold = true`
