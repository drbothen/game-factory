# BC-13.02.003: Esports Replay Format — CAP-003 Spine Reuse

## Description

When the esports lane is active, the factory generates a `replay-format` artifact
declaring the esports demo/replay mode for the game. This is NOT a new replay mechanism —
it is the CAP-003 replay-regression spine (deterministic-input replay or state-snapshot
replay, tiered by the engine adapter's determinism tier) exposed and labeled as an
esports-facing feature: the deterministic demo, killcam, free-camera, and match-result
audit functions. For T1 (bitwise determinism, e.g., Bevy+Rapier), this is essentially
free: the factory already records, replays, and hash-verifies simulation state. The
`replay-format` artifact adds round-trip integrity verification and killcam-window
determinism on top.

## Preconditions

1. The esports lane is active (`esports_enabled: true`) in the validated genre profile.
2. The engine adapter's determinism tier has been declared and conformance-verified
   (CAP-002, BC per DI-004).
3. The CAP-003 replay regression infrastructure is operational for the game spec (golden
   state recorded, input stream logging enabled).

## Postconditions

1. A `replay-format` artifact is generated declaring:
   - `replay_mode`: `deterministic_input` (T1) | `snapshot_stream` (T2/T3) | `none`
     (degraded — no fixed timestep or no RNG injection).
   - `correctness_gate`: reference to the CAP-003 `replay-regression-contract` for the
     same engine adapter.
   - `features`: which of {demo, killcam, free_camera, match_result_audit} are enabled.
   - `round_trip_integrity`: boolean declaring whether the artifact will be verified with
     round-trip serialization testing.
2. For `replay_mode: deterministic_input` (T1): the esports demo is verified to produce
   bit-identical simulation state to the live match on re-simulation.
3. For `replay_mode: snapshot_stream` (T2/T3): the demo is verified to restore the nearest
   snapshot and replay forward deterministically to any seeked timestamp.
4. For `replay_mode: none`: the `demo`, `free_camera`, and `match_result_audit` features
   are set to unavailable; a `human_playtest_evidence` requirement is recorded.
5. Killcam correctness (T1): re-simulation of the bounded window ending at the death frame
   produces the authoritative kill determination.

## Factory Mapping (determinism tier → replay form)

| Determinism tier | Esports replay form | Factory regression gate |
|-----------------|--------------------|-----------------------|
| T1 (Bevy+Rapier, bitwise) | `deterministic_input` demo, free-cam, re-sim, killcam | Exact snapshot-hash equality (CAP-003 convergence dim #2) |
| T2 (Unity PhysX, pinned-runner) | Input demo on pinned build OR snapshot stream | Pinned-runner snapshot diff |
| T3 (Godot FP, tolerance-window) | State-snapshot stream only | Tolerance-window metric diff |
| none (no fixed-timestep or no RNG injection) | State-snapshot stream only, or unavailable | Human-playtest evidence requirement |

## Invariants

1. The `replay-format` artifact always references the CAP-003 `replay-regression-contract`
   for the same engine adapter — it does not define replay correctness independently.
2. Esports replay correctness (for T1) is `hash(replay(inputs)) == hash(live)` — the same
   machine-verifiable assertion the replay-regression gate already makes.
3. The `match_result_audit` feature (re-simulate the input log, assert the recorded
   outcome) is available if and only if `replay_mode: deterministic_input`.
4. No esports replay feature requires modifying the CAP-003 spine — it is additive
   configuration only.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | T1 adapter replay with floating-point non-determinism introduced by a new code change | Hash mismatch detected by CAP-003 regression gate before `replay-format` features are exposed; esports replay blocked until determinism is restored |
| EC-002 | T2 adapter: pinned CI runner unavailable | `replay_mode` degrades to T3 tolerance; `snapshot_stream` mode activated; `match_result_audit` set unavailable |
| EC-003 | Killcam requested for a death event that occurred within the first 3 frames (before any snapshot exists) | Killcam window bounded to available simulation history; returns available frames rather than erroring |
| EC-004 | Replay file serialized to disk and deserialized: round-trip integrity check | Re-simulation of deserialized replay produces bit-identical state to original (T1 only) |
| EC-005 | Esports lane active but game genre has no competitive PvP (e.g., co-op only) | `replay-format` artifact generated with all features available; `match_result_audit` applies to co-op run audit |

## Canonical Test Vectors

| Input | Expected Output | Category |
|-------|----------------|----------|
| T1 adapter, record match inputs, re-simulate | `hash(replay_state) == hash(live_state)` at all golden checkpoints | happy-path |
| T1 adapter, killcam: inject death event at frame 1000, request 5s killcam | Re-simulation of frames 940–1000 produces identical kill determination | happy-path |
| T2 adapter, snapshot stream: seek to T=30s | Nearest snapshot at T=28s located; replay forward 2s; state within T2 tolerance | happy-path |
| `replay_mode: none` declared | All features set `available: false`; human_playtest_evidence requirement recorded | edge-case |
| Round-trip: serialize replay to file, deserialize, re-simulate | State hash identical to non-round-tripped replay | edge-case |
