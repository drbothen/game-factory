# BC-13.03.004: UGC Distribution Adapter — mod.io Round-Trip Conformance

## Description

When the modding lane declares UGC distribution, the factory generates and validates a
`ugc-distribution-adapter` seam configuration. The reference adapter is mod.io — the
engine-agnostic, console-authorized UGC backend. The adapter must pass a conformance
suite: publish a test mod to the mod.io test environment, browse/search for it, subscribe,
and install. This mirrors the engine adapter conformance pattern (CAP-002): capability-
negotiated, declare-and-degrade, with mod.io as the reference target. Steam Workshop is
a supported secondary adapter for Steam-only distribution. Paid UGC (Marketplace
monetization) requires explicit human copyright-vetting and is always `human-gated`.

## Preconditions

1. The modding lane is active (`modding_enabled: true`) and `modding_config.distribution`
   declares a UGC backend.
2. For `backend: modio`: the mod.io test environment is accessible (mod.io provides a
   dedicated test/sandbox environment at `api.test.mod.io`).
3. The adapter has a configured API key (read-only) and OAuth2 token (write operations).
4. A conformance test mod exists with a valid `manifest.json` and at least one asset file.

## Postconditions

1. A `ugc-distribution-adapter` seam configuration artifact is generated declaring:
   - `backend`: `modio` (reference, engine-agnostic, console-grade) or `steam_workshop`
     (Steam-only secondary).
   - `capabilities`: the subset of UGC distribution capabilities the backend supports
     (from the capability table below).
   - `conformance_status`: `pass`, `fail`, or `skip` (skip for non-test environments).
2. Conformance suite passes:
   - Publish: POST a mod to the test environment; receive a valid mod ID in response.
   - Browse: GET the mod by ID; metadata matches the published manifest.
   - Search: GET mods filtered by a KVP metadata field; the test mod appears in results.
   - Subscribe: subscribe to the mod; subscription appears in user's subscription list.
   - Install: download the mod file; verify SHA256 checksum matches the published value.
3. Rate-limit handling: if the test environment returns HTTP 429, the adapter retries with
   the `retry-after` value; conformance test does not count rate-limit as a failure.
4. Paid UGC (`monetization: marketplace`) is declared `human-gated`; no autonomous
   vetting or payment processing occurs.

## UGC Distribution Capability Surface

| Capability | mod.io | Steam Workshop | Notes |
|-----------|--------|----------------|-------|
| host | full | full | mod.io: 8 GB/file (verified) |
| browse_search | full | full | mod.io: or_fields filtering |
| dependencies | full | partial | mod.io: first-class REST endpoint |
| versioning | full | full | — |
| subscription_sync | full | full | — |
| moderation_queue | full | none | mod.io: Content-Approval queue (required for console cert) |
| console_auth | full | none | mod.io: Xbox/PS/Switch authorized; Workshop: PC-only |
| monetization_marketplace | human-gated | partial | Paid UGC requires copyright vetting (human gate) |
| cross_platform | full | none | mod.io: engine-agnostic; Workshop: Steam silo |

## Invariants

1. mod.io is the reference, engine-agnostic adapter; Steam Workshop is a Steam-only
   secondary adapter. The default recommendation for new games is mod.io.
2. The adapter never bypasses mod.io's `Content-Approval` queue — mods are hidden pending
   moderator approval on console targets.
3. The `monetization_marketplace` capability is always `human-gated`: paid UGC requires
   human copyright-vetting before activation (DI-006).
4. Adapter conformance runs against the mod.io test environment (`api.test.mod.io`), not
   the live environment.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | mod.io test environment returns HTTP 503 (service unavailable) | Conformance test is skipped with `conformance_status: skip`; artifact generated with warning; not a blocking failure |
| EC-002 | Mod file upload exceeds 8 GB | Upload rejected with `E-MOD-009` (file size exceeds platform limit); adapter records the limit in the capability declaration |
| EC-003 | Subscription sync requested on a platform without mod.io console SSO configured | Capability reported as `none` for that platform; degradation surfaced in capability manifest |
| EC-004 | `monetization_marketplace` declared in config without human copyright-vetting | `E-MOD-010` emitted; marketplace capability set to `human-gated`; DI-006 task surfaced |
| EC-005 | Steam Workshop adapter: cross-platform mod content requested | `E-MOD-011` (Steam silo: Steam Workshop content cannot reach non-Steam platforms); operator must use mod.io for cross-platform |

## Canonical Test Vectors

| Input | Expected Output | Category |
|-------|----------------|----------|
| Publish test mod to mod.io test env | HTTP 201; mod ID returned; conformance round: browse by ID returns matching metadata | happy-path |
| Search by KVP metadata on test mod | Test mod appears in filtered results | happy-path |
| Install test mod: download, verify SHA256 | Checksum matches; `conformance_status: pass` | happy-path |
