# BC-13.04.002: Marketing Asset Manifest Completeness

## Description

When the marketing lane is active, the factory generates a `marketing-asset-manifest`
— a complete, machine-verified index of all marketing assets produced for the game,
grouped by asset type, with provenance references and conformance status for each.
The manifest is the audit record that ties store page assets, trailers, press kit
materials, and capture-recipe outputs to their provenance sidecars (DI-003). A complete
manifest requires no missing required asset types for the declared target platforms.
Asset quality, artistic direction, and campaign strategy are explicitly human-shell and
not part of this contract.

## Preconditions

1. The marketing lane is active with at least one declared target platform.
2. The asset pipeline (CAP-004) has completed generation for all marketing asset
   generation requests.
3. All generated assets have provenance sidecars with `disclosure_class` populated.
4. The store page conformance check (BC-13.04.001) has run and its results are available.

## Postconditions

1. A `marketing-asset-manifest` artifact is generated containing:
   - A complete enumeration of all generated marketing assets, grouped by type.
   - For each asset: `path`, `asset_type`, `platform`, `dimensions`, `format`,
     `disclosure_class`, `conformance_status`, `provenance_sidecar_path`.
   - A completeness check: for each required asset type per platform, whether the asset
     is present and conformant.
   - A `manifest_complete` boolean: `true` iff all required asset types for all declared
     platforms are present with `conformance_status: pass` or `human_gated`.
2. If any required asset type is missing, `manifest_complete: false` and `E-MKT-003`
   (missing required marketing asset) is emitted listing the platform and asset type.
3. The press kit declaration is included if `marketing_config.press_kit: true`: a
   `press-kit` sub-section lists the generated presskit() format files (data.xml,
   screenshots, logo variants, factsheet).

## Required Asset Types by Platform

| Platform | Required types | Optional |
|---------|---------------|---------|
| Steam | header_capsule, small_capsule, main_capsule, vertical_capsule, ≥5 screenshots, trailer | background, page_background |
| Apple App Store | app_icon, ≥2 screenshots (per declared device targets) | app_preview |
| Google Play | app_icon, feature_graphic, ≥2 screenshots | — |
| Xbox (public specs only) | hero_art, trailer_thumbnail, ≥1 screenshot | box_art (human_gated) |

## Invariants

1. The manifest is never partial — it is generated only after all asset generation
   requests have completed (pass or fail).
2. `manifest_complete: true` requires every required asset for every declared platform
   to be present; optional assets may be absent.
3. Every asset in the manifest must have a valid provenance sidecar path pointing to an
   existing sidecar with `disclosure_class` populated (DI-003 enforced at manifest level).
4. The manifest is immutable once generated for a given game spec + genre profile version;
   regeneration requires a version bump.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | One of five required Steam screenshots fails conformance | `manifest_complete: false`; `E-MKT-003` (insufficient conformant screenshots); human task to regenerate |
| EC-002 | Press kit disabled (`press_kit: false`) but press-kit assets were previously generated | Manifest does not include press-kit section; no error; pre-existing press-kit files are not referenced |
| EC-003 | Asset has provenance sidecar but `disclosure_class` field is empty | `E-MKT-004` (incomplete provenance sidecar); DI-003 violation; asset listed as non-conformant in manifest |
| EC-004 | Marketing lane active but all platform configs are removed from genre profile | `E-GLG-001` (schema validation: at least one platform required when marketing lane active); manifest not generated |
| EC-005 | Trailer generation failed (e.g., capture pipeline error) | Manifest records trailer as `conformance_status: fail`; `manifest_complete: false`; human task to resolve |
