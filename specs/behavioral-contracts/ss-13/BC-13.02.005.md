# BC-13.02.005: Tournament Mode Spec — Bracket Combinatorics and Match-Result Audit

## Description

When the esports lane declares tournament mode, the factory generates a `tournament-mode-spec`
artifact defining the bracket format and its deterministic structural correctness properties.
Bracket formats (single/double elimination, Swiss, round-robin, GSL) are pure combinatorial
structures: every participant placed exactly once, progression rules deterministic,
Swiss pairing avoiding rematches and pairing equal records, round-robin scheduling every
pair exactly once. Match-result audit — re-simulating the recorded input log and asserting
the claimed outcome — is available when `replay_mode: deterministic_input` is declared.
Running the actual event (logistics, prize disbursement, casting, league admin) is
irreducibly human-operational and out of factory scope.

## Preconditions

1. The esports lane is active (`esports_enabled: true`) in the validated genre profile.
2. `esports_config.tournament` is present and declares:
   - `format`: one of `single_elimination`, `double_elimination`, `swiss`, `round_robin`, `gsl_groups`.
   - `seeding_function`: one of `rank_based`, `random`, `manual`.
   - `participant_count`: a positive integer consistent with the format's constraints.
3. If `match_result_audit: true`, `replay_mode: deterministic_input` must be declared
   (BC-13.02.003); otherwise `match_result_audit` is set `unavailable`.

## Postconditions

1. A `tournament-mode-spec` artifact is generated containing:
   - The bracket format, seeding function, and participant count.
   - The applicable structural correctness invariants from the catalog below.
   - `match_result_audit` availability declared.
2. The bracket structure is machine-verifiable as satisfying all format invariants.
3. If `match_result_audit: true`: the audit procedure is declared — re-simulate the input
   log (per BC-13.02.003 T1 spine), assert the recorded final state matches the claimed
   result.
4. The seeding function, when `rank_based`, produces a deterministic bracket placement
   such that the highest seed cannot face the second-highest seed in the first round.

## Structural Correctness Invariant Catalog

| Format | Invariant ID | Invariant |
|--------|-------------|-----------|
| All | INV-TRN-01 | Every participant placed exactly once in the bracket at the start |
| All | INV-TRN-02 | Bracket progression is a deterministic function of match results |
| Single elimination | INV-TRN-03 | Losers are eliminated immediately; winner advances exactly one round per win |
| Double elimination | INV-TRN-04 | One loss moves player to losers bracket (not elimination); two losses = elimination |
| Double elimination | INV-TRN-05 | Losers bracket is correctly fed from winners bracket (specific round pairing pattern) |
| Swiss | INV-TRN-06 | No player rematch within the same tournament |
| Swiss | INV-TRN-07 | Players with equal records are paired in each round |
| Round-robin | INV-TRN-08 | Every pair of participants meets exactly once |
| GSL groups | INV-TRN-09 | Groups are balanced; advancement rules are deterministic |
| All (rank-based seeding) | INV-TRN-10 | Seed 1 and Seed 2 cannot be placed in the same bracket half (top-seed early collision avoidance) |

## Invariants

1. Bracket structures are pure combinatorial functions of (format, participant count,
   seeding order) — no randomness beyond seeded randomization when `seeding_function:
   random`, in which case the seed is recorded.
2. `match_result_audit` requires T1 determinism (BC-13.02.003); this dependency is
   declared in the artifact and enforced at schema validation.
3. Running the actual event (prize disbursement, schedule logistics, format-choice policy)
   is out of factory autonomous scope — declared explicitly in the artifact's `human_scope`
   field.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Swiss tournament: odd number of participants | One player receives a bye each round; bye is treated as a win for pairing purposes; byes are evenly distributed |
| EC-002 | Double elimination: player loses twice in the winners bracket before reaching losers bracket boundary | Schema validation rejects this; standard double-elim logic enforced |
| EC-003 | `participant_count: 1` (single participant) | Schema validation fails: tournament requires ≥2 participants |
| EC-004 | `seeding_function: manual` with no seed list provided | Schema validation fails (E-GLG-001): manual seeding requires seed list |
| EC-005 | `match_result_audit: true` with `replay_mode: snapshot_stream` (not deterministic_input) | `match_result_audit` overridden to `unavailable`; warning emitted (E-GLG-005); artifact generated with audit unavailable |

| Input | Expected Output | Category |

| 8-player double elim: player A loses twice | Player A eliminated; losers bracket advanced correctly per INV-TRN-04 | edge-case |
