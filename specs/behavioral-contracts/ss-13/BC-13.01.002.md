# BC-13.01.002: Inactive Lane Zero-Artifact Guarantee

## Description

When a production lane is declared inactive in the genre profile (e.g.,
`esports_enabled: false`, `modding_enabled: false`), the factory MUST produce zero
lane-specific artifacts for that lane in the output tree. No ranked artifacts, no
matchmaking configurations, no mod-api contracts, no UGC schemas, no store-page
manifests — nothing that would not exist if the lane had never been mentioned. The
universal core artifacts are produced unchanged. This is the load-bearing invariant of
the entire genre-gated architecture: a lane's activation state must be binary and
verifiable, not merely advisory.

## Preconditions

1. The genre profile has passed schema validation (BC-13.01.001).
2. The lane in question is set to its inactive value in the validated genre profile (e.g.,
   `esports_enabled: false`).
3. The pipeline has completed its full production run for the game spec.

## Postconditions

1. The output artifact tree for the production run contains zero files in the
   lane-specific artifact namespace for the inactive lane (enumerated per lane in the
   Lane Artifact Namespaces table below).
2. The core artifact set (design specs, balance data, narrative, audio manifests, base
   code, QA artifacts) is identical to what would have been produced if the lane option
   had been omitted entirely from the genre profile.
3. The convergence report records the lane as inactive with `artifact_count: 0` for that
   lane.

## Lane Artifact Namespaces (machine-checkable)

| Lane | Inactive trigger | Artifacts that MUST NOT appear when inactive |
|------|-----------------|----------------------------------------------|
| Esports / Competitive | `esports_enabled: false` | `ranking-system-contract.*`, `matchmaking-fairness-invariants.*`, `replay-format.*` (esports variant), `spectator-spec.*`, `tournament-mode-spec.*`, `broadcast-stats-contract.*` |
| Modding / UGC | `modding_enabled: false` | `mod-api-contract.*`, `ugc-content-schema.*`, `ugc-distribution-adapter.*`, `mod-load-spec.*`, `mod-sdk.*` |
| Marketing / GTM | `marketing_lane: null` or `marketing_lane.enabled: false` | `store-page-spec.*` (platform-specific), `marketing-asset-manifest.*`, `press-kit.*` |

## Invariants

1. **Strict zero:** an inactive lane produces no artifacts whatsoever in its namespace.
   There is no concept of a "placeholder" or "stub" artifact for an inactive lane.
2. **Core invariance:** the artifact content of all non-lane-specific files is bitwise
   identical regardless of which lanes are active or inactive. A lane's activation state
   may never alter core artifact content.
3. **Namespace isolation:** lane-specific artifact namespaces are disjoint from each other
   and from the core namespace. There is no overlap that would allow a lane artifact to
   masquerade as a core artifact.
4. The zero-artifact property is machine-verifiable as a directory/file-list check on
   the output tree, scoped to the lane-specific namespace.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | All three optional lanes are inactive | Output tree contains only core artifacts; convergence report shows `artifact_count: 0` for each lane |
| EC-002 | Lane was active in a prior build, then set to inactive in a subsequent build | Incremental build: prior lane artifacts are removed from the output tree; not just suppressed from new generation |
| EC-003 | A lane config object is present in the genre profile but `lane_enabled: false` | Lane remains inactive; config object is validated but its content has no effect; zero lane artifacts produced |
| EC-004 | Pipeline encounters an error during core artifact generation while a lane is inactive | Error handling is independent of lane state; inactive lane status does not change |
| EC-005 | Two lanes are simultaneously inactive | Each lane's namespace independently contains zero artifacts; no cross-lane contamination |
