# BC-13.02.001: Ranking System Contract — Pure-Function Math Invariants

## Description

When the esports lane is active, the factory generates a `ranking-system-contract`
declaring the chosen rating model and its machine-checkable invariant set. The rating
update function is a pure, deterministic function: given current ratings and observed
match results, it produces new ratings with no side effects and no hidden state. The
contract pins the mathematical invariants that must hold for the chosen model, enabling
property-based testing and optional formal hardening. This is the strongest BC/VP target
in the entire AAA research corpus.

Supported models: `elo`, `glicko`, `glicko2`, `trueskill`, `trueskill2`, `weng_lin`, `custom`.

## Preconditions

1. The esports lane is active (`esports_enabled: true`) in the validated genre profile.
2. `esports_config.rating_model` is set to a valid enum value.
3. For `glicko2`: the corrected Step-5 iterative procedure (2012-02-22, item-4(b) revised
   2022-03-22 `< → <=`) is the pinned implementation target.
4. For `custom`: a fully-specified custom update function and its invariant declarations
   are provided.
5. The rating library reference implementation is version-pinned in the adapter manifest.

## Postconditions

1. A `ranking-system-contract` artifact is generated containing:
   - The rating model identifier and version-pinned library reference.
   - The model parameter declarations (K, c, τ, β, ε, σ₀, etc. as applicable per model).
   - The active invariant set from the table below.
2. A property-based test suite is generated covering every declared invariant.
3. The contract declares its validation method as `property_based_testing` (with optional
   `formal_hardening` flag).
4. The rating update function, when invoked with well-formed inputs, produces outputs
   satisfying all declared invariants without exception.

## Invariant Catalog by Model

### Elo (all apply)

| ID | Invariant | Expression |
|----|-----------|------------|
| INV-ELO-01 | Zero-sum (shared K) | `R_A' + R_B' = R_A + R_B` |
| INV-ELO-02 | Expected-score bounds | `0 < E_A < 1` for all finite rating differences |
| INV-ELO-03 | Expected-score monotonicity | `E_A` strictly increases with `R_A − R_B` |
| INV-ELO-04 | Surprise monotonicity | For a win, gain `K(1 − E_A)` is larger when defeating a higher-rated opponent |
| INV-ELO-05 | Gain sign matches outcome | `R_A' > R_A` iff `S_A > E_A`; `R_A' < R_A` iff `S_A < E_A` |

### Glicko (add to Elo invariants)

| ID | Invariant | Expression |
|----|-----------|------------|
| INV-GLK-01 | RD upper bound | `RD' ≤ 350` |
| INV-GLK-02 | Activity monotonicity — play | `RD' < RD_old` when ≥1 game played in period |
| INV-GLK-03 | Activity monotonicity — inactivity | `RD' > RD_old` when 0 games played in period |
| INV-GLK-04 | RD positivity | `RD' > 0` always |

### Glicko-2 (replace Glicko; pin corrected Step-5)

| ID | Invariant | Expression |
|----|-----------|------------|
| INV-GL2-01 | RD upper bound | `RD' ≤ 350` (on reconverted scale) |
| INV-GL2-02 | Activity monotonicity — play | `RD' < RD_old` when ≥1 game played |
| INV-GL2-03 | Activity monotonicity — inactivity | `RD' > RD_old` when 0 games played |
| INV-GL2-04 | Volatility positivity | `σ' = exp(x/2) > 0` always (Illinois algorithm output) |
| INV-GL2-05 | Illinois convergence determinism | Same inputs → same σ' to tolerance 1e-6 |
| INV-GL2-06 | Corrected Step-5 | Implementation uses 2012-02-22 corrected procedure; item 4(b) uses `<=` (2022-03-22 revision) |

### TrueSkill / TrueSkill2

| ID | Invariant | Expression |
|----|-----------|------------|
| INV-TS-01 | σ-contraction | `σ_i' < σ_i` after conditioning on any game |
| INV-TS-02 | Conservative-rating ordering | `μ − 3σ` is non-decreasing in μ, non-increasing in σ |
| INV-TS-03 | Permutation equivariance | Identical players/opponents/outcomes → identical posteriors |
| INV-TS-04 | Match quality bounds | `0 < quality(μ_i, σ_i, μ_j, σ_j, β) ≤ 1`; quality maximized at equal skills |

### Weng-Lin / OpenSkill

| ID | Invariant | Expression |
|----|-----------|------------|
| INV-WL-01 | σ-contraction | `σ_i' < σ_i` after any game |
| INV-WL-02 | Monotonicity | Higher μ → higher predicted finish (BTL/Plackett-Luce) |
| INV-WL-03 | Permutation equivariance | Symmetric team configurations → symmetric update |

## Invariants (contract-level)

1. The rating update function has no I/O, no global state access, and is deterministic — it
   is a pure function testable in isolation.
2. The `ranking-system-contract` artifact pins the exact library version and commit for the
   reference implementation (Semport-style pinning).
3. The invariant set for the chosen model is non-empty and covers at minimum the conservation,
   monotonicity, and bound invariants from the catalog above.
4. No model parameter may be set to a value that trivially violates an invariant (e.g.,
   K ≤ 0 for Elo).

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Elo: both players have the same rating | `E_A = E_B = 0.5`; zero-sum invariant holds; winner gains `K/2`, loser loses `K/2` |
| EC-002 | Glicko-2: player has RD = 350 (maximum uncertainty, no prior games) | First game: RD decreases toward `RD_min`; volatility update runs correctly |
| EC-003 | Glicko-2: all games in a rating period result in draws (`S = 0.5` for all) | Ratings unchanged; RD decreases; volatility decreases |
| EC-004 | TrueSkill: team with single player vs team with multiple players | Team performance = sum of member performances; EP runs correctly; per-player σ decreases |
| EC-005 | `custom` rating model specified without declaring its invariants | Schema validation fails with `E-GLG-003`: custom model must declare invariants |
| EC-006 | Illinois algorithm: initial bracket does not contain a root | Implementation must detect this case and return an error rather than loop infinitely |

## Canonical Test Vectors

| Input | Expected Output | Category |
|-------|----------------|----------|
| Elo: R_A=1500, R_B=1500, K=32, S_A=1 (win) | R_A'=1516, R_B'=1484; sum=3000 (conservation) | happy-path |
| Elo: R_A=1200, R_B=1800, K=32, S_A=1 (upset win) | Gain > 16 (surprise monotonicity: beating higher-rated); R_A'+R_B'=3000 | happy-path |
| Glicko-2: defaults (μ=1500, RD=350, σ=0.06, τ=0.5), one win vs r_j=1400, RD_j=30 | RD' < 350; σ' > 0; Illinois converges in finite iterations | happy-path |
| TrueSkill: μ_A=μ_B=25, σ_A=σ_B=25/3, β=25/6 | `quality(A,B) ≈ 1.0` (equal skills → max quality); after match: both σ' < σ | happy-path |
| Glicko-2 with zero games in rating period | RD' > RD (uncertainty grows); rating unchanged; σ' updated per volatility formula | edge-case |
| Elo: K=0 | Contract validation rejects K=0 as invariant-violating parameter | error |
