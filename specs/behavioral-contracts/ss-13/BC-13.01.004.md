# BC-13.01.004: Genre Profile Default Enforces NFT/Web3 Off-By-Default (DI-011)

## Description

When a game project is initialized without an explicit `business-model-spec` declaration
enabling NFT, blockchain token, or web3 mechanics, the factory must apply the
`nft_mechanics: false` and `web3_enabled: false` defaults in the genre profile. Activating
NFT/web3 mechanics requires an explicit opt-in declaration in `business-model-spec` with
acknowledgment of the PEGI-18 minimum rating consequence. This BC enforces DI-011 at the
genre profile validation level as a genre-gated activation gate.

Enforcement is done both at genre profile schema validation time and at pipeline
initialization — any downstream lane or artifact generator that checks the genre profile
will receive these defaults if they were not explicitly overridden.

## Preconditions

1. A game project is being initialized with a genre profile document.
2. The genre profile is validated against the canonical genre-profile schema.
3. The project's `business-model-spec` is either absent (new project default) or
   present (explicit declaration with acknowledged consequences).

## Postconditions

1. When no `business-model-spec` is present in the project:
   - The validated genre profile contains `nft_mechanics: false`
   - The validated genre profile contains `web3_enabled: false`
   - The validated genre profile contains `blockchain_token: false`
   - These defaults are injected by the schema defaulting mechanism, not left absent
2. When a `business-model-spec` is present and declares `nft_mechanics: true` or
   `web3_enabled: true`:
   - The genre profile activates the corresponding field
   - The validation gate checks that `business-model-spec.pegi_18_acknowledged: true`
     is set; if absent, validation fails with `E-GENRE-005`
   - A human-gated review task is surfaced: "NFT/Web3 mechanics activated — PEGI 18
     minimum rating applies; legal review required before distribution"
   - **Console platform cert-preflight routing (I8):** For any `target_platform` in
     `{xbox, psn, switch}`, the NFT/web3 activation is forwarded to the cert pre-flight
     harness (BC-9.01.001) as an additional platform-policy check entry. The
     `cert-preflight-report` for console targets must include a `nft_blockchain_policy`
     check slot with result `REQUIRES_HUMAN_REVIEW` and message: "NFT/web3 mechanics
     declared — verify platform holder NFT/blockchain policy compliance before cert
     submission (Sony, Microsoft, and Nintendo each maintain independent policies that
     may block certification independent of age rating)." The `convergence-report
     .dimensions.cert_preflight` is set to `AMBER` (not PASS) until this slot is
     cleared by human review. This signal must appear **before** any upload to the
     console distribution adapter (BC-9.03.001 / BC-9.03.002 / BC-9.03.003).
3. The factory never generates NFT smart contract code, web3 wallet integration,
   or blockchain token minting/transfer scaffolding without an explicit opt-in declaration.
4. The inactive-lane zero-artifact guarantee (BC-13.01.002) covers NFT/web3 lane
   artifacts: when `nft_mechanics: false` and `web3_enabled: false`, no NFT/web3
   artifacts are generated anywhere in the pipeline.

## Invariants

1. NFT mechanics and web3 features are always `false` in the default genre profile — no
   partial default or opt-out-required default is permitted.
2. This default is not overridable via flag, agent instruction, or pipeline parameter
   without an explicit `business-model-spec` document in the project repository.
3. The PEGI-18-acknowledged check is non-bypassable when NFT/web3 is activated.
4. Riot Vanguard and similar non-licensable anti-cheat dependencies do not become activated
   via any web3/NFT flag (these are separate concerns; the web3 flag is not a platform
   privilege escalation path).

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | New project initialized with empty genre profile | Schema validator injects `nft_mechanics: false`, `web3_enabled: false`, `blockchain_token: false` as defaults; validation passes |
| EC-002 | Genre profile explicitly sets `nft_mechanics: true` without `business-model-spec` | Validation fails with `E-GENRE-004`; human task surfaced requiring `business-model-spec` creation |
| EC-003 | Genre profile has `business-model-spec` with `nft_mechanics: true` but `pegi_18_acknowledged: false` | Validation fails with `E-GENRE-005`; pipeline blocked until acknowledgment is provided |
| EC-004 | Genre profile has `business-model-spec` with both `nft_mechanics: true` and `pegi_18_acknowledged: true`, Steam target only | Validation passes; NFT lane activated; human-gated legal review task surfaced; PEGI 18 minimum injected into compliance checklist; no console cert-preflight routing needed (non-console target) |
| EC-005 | Project attempts to merge a PR that adds `web3_enabled: true` via pipeline parameter (not business-model-spec) | Gate fails; E-GENRE-004 emitted; explicit `business-model-spec` document required in repo |
| EC-006 | Project uses cosmetic blockchain feature (e.g., NFT-based avatar frame) | Treated as `nft_mechanics: true` — PEGI-18 consequence applies to any NFT mechanic regardless of cosmetic vs. functional nature |
| EC-007 | Project has `nft_mechanics: true`, targets both `steam` and `psn` | Console cert-preflight routing fires for `psn`; Steam target unaffected by console routing; both the PEGI-18 legal review task and the `psn` cert-preflight REQUIRES_HUMAN_REVIEW slot are surfaced |
| EC-008 | Project has `nft_mechanics: true`, targets `switch` | Nintendo NFT/blockchain policy check added to Switch cert-preflight; `cert_preflight` dimension = AMBER until human review confirms Nintendo policy compliance |
