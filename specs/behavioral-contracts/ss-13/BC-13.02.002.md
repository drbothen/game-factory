# BC-13.02.002: Matchmaking Fairness Invariants

## Description

When the esports lane declares matchmaking, the factory generates a
`matchmaking-fairness-invariants` artifact specifying the structural correctness
properties the matchmaker must satisfy. The factory verifies the *structural* invariants
(team-MMR balance, predicted win probability bounds, skill-band containment, queue-time
bound, MWPM structural validity if EOMM-style); it does NOT determine the engagement-vs-
fairness policy objective, which is a declared human/product parameter. Autonomous
LTV/engagement maximization without a declared ethics contract is a factory defect (DI-005).

## Preconditions

1. The esports lane is active (`esports_enabled: true`) and `esports_config.matchmaking`
   is present and validated (BC-13.01.001).
2. `esports_config.matchmaking.backend` declares the matchmaking service (e.g.,
   `nakama`, `eos`, `playfab`, `flexmatch`, `custom`).
3. `esports_config.matchmaking.objective` is declared by the human/product team as
   one of: `fairness` (equal-skill), `engagement` (EOMM-style MWPM), or `hybrid`.
4. A rating model is declared (BC-13.02.001) to supply the MMR values for fairness checks.

## Postconditions

1. A `matchmaking-fairness-invariants` artifact is generated containing all invariants
   from the table below.
2. The artifact declares the policy objective as a parameter (not as a verified value).
3. A property-based test suite is generated covering all declared fairness invariants.
4. If `objective: engagement` is declared, the MWPM structural validity invariants are
   included and the artifact records that the engagement/fairness tradeoff is a
   human-declared policy.
5. If `objective: engagement` is declared without a `monetization-ethics-contract`
   review, the pipeline emits `E-GLG-004` warning (engagement objective without ethics
   review).

## Fairness Invariant Catalog

| ID | Invariant | Machine-verifiable | Description |
|----|-----------|-------------------|-------------|
| INV-MMR-01 | Team MMR balance | YES | `|mean_MMR(team_A) − mean_MMR(team_B)| ≤ fairness_tolerance` |
| INV-MMR-02 | Predicted win probability band | YES | `|PWP − 0.5| ≤ pwp_tolerance` (e.g., 0.05) |
| INV-MMR-03 | Skill-band containment | YES | No player matched outside their declared skill band |
| INV-MMR-04 | Queue-time upper bound | YES | Matching occurs within `max_queue_seconds` |
| INV-MMR-05 | Visible-rank monotonicity (shape) | YES (shape only) | `dR_visible/dμ_MMR ≥ 0` (non-decreasing) |
| INV-MMR-06 | MWPM validity (if EOMM) | YES | Perfect matching: every queued player paired exactly once; no double-booking; edge weights symmetric |
| INV-MMR-07 | Engagement policy is declared | YES (presence) | `objective` field present and set to a valid enum value |
| INV-MMR-08 | No autonomous engagement maximization | YES (policy check) | `objective: engagement` requires explicit human declaration and ethics review flag |

## Invariants (contract-level)

1. The matchmaking fairness invariants are purely structural — they assert the shape and
   bounds of the matchmaking function, not the specific engagement policy chosen.
2. The `objective` field is a human/product parameter; the factory enforces only that it
   is declared and not silently defaulting to engagement maximization.
3. EOMM-derived engagement optimization (MWPM over churn-risk graph) is a supported
   objective but requires explicit opt-in and ethics review flag.
4. Smurf detection anomaly thresholds feed human review, never autonomous bans.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Queue has only 1 player; perfect matching impossible | Queue-time bound still applies; system emits "insufficient players" status rather than timing out silently |
| EC-002 | `objective: engagement` declared without ethics review flag | `E-GLG-004` warning emitted; artifact generated with warning annotation; pipeline continues |
| EC-003 | `objective: engagement` and `fairness_tolerance` set to 0 (strict equal-MMR) | Both engagement and strict-fairness invariants apply simultaneously; MWPM with strict edge-weight constraint |
| EC-004 | Skill band configuration has overlapping bands | Schema validation fails with `E-GLG-001`; no matchmaking artifacts generated |
| EC-005 | `visible_rank` mapping function has a region where it is non-monotone (e.g., promotion hysteresis) | INV-MMR-05 is evaluated on the overall shape; hysteresis regions are documented as exceptions in the artifact |

## Canonical Test Vectors

| Input | Expected Output | Category |
|-------|----------------|----------|
| Two teams: team_A mean MMR=1500, team_B mean MMR=1500; fairness_tolerance=50 | INV-MMR-01 passes (difference=0); INV-MMR-02 passes (PWP=0.5) | happy-path |
| EOMM objective: queue of 4 players with churn-risk weights; MWPM produces 2 pairs | INV-MMR-06: each player paired exactly once; edge weights symmetric; INV-MMR-07: objective declared | happy-path |
| `objective` field absent from config | Schema validation fails (E-GLG-001): objective required | error |
| Team MMR difference = 200; fairness_tolerance = 50 | INV-MMR-01 fails; match rejected; players re-queued | edge-case |
| Player outside declared skill band force-matched | INV-MMR-03 fails; match rejected | error |
