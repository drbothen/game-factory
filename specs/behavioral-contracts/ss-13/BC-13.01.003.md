# BC-13.01.003: Lane Activation Idempotency

## Description

Activating the same production lane twice within the same game spec build — using the same
validated genre profile with the same input hash — produces bitwise-identical lane artifacts
on both activations. There is no "first-time initialization" state that differs from
subsequent activations. This contract is the lane-specific extension of the factory's
general determinism requirement: the lane pipeline is a pure function of its inputs.

## Preconditions

1. The genre profile has passed schema validation (BC-13.01.001) on both invocations.
2. Both invocations use the same genre profile document with the same input hash.
3. The same lane is declared active on both invocations (same lane config object).
4. No external state (filesystem, network, random seed) changes between invocations that
   would legitimately affect lane artifact content.

## Postconditions

1. All lane-specific artifacts produced by invocation 2 are bitwise-identical to the
   corresponding artifacts produced by invocation 1.
2. The artifact set produced by invocation 2 contains exactly the same files (same paths,
   same count) as invocation 1.
3. The input hash recorded in the pipeline artifact log is identical for both invocations.

## Invariants

1. Lane artifact generation is a pure function of (game spec inputs, genre profile, lane
   config). Same inputs → same outputs. This invariant holds across restarts, cache
   misses, and re-runs.
2. No lane artifact contains a build timestamp, random nonce, or other non-deterministic
   value that would cause idempotency to fail.
3. The idempotency property is testable as: `hash(run1_artifacts) == hash(run2_artifacts)`
   for the lane-specific artifact subset.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Lane activated, partial failure on first run (some artifacts written before error); second run starts from clean state | Second run produces bitwise-identical artifacts to a successful first run; partial outputs from the failed first run do not affect the result |
| EC-002 | Lane is activated, then deactivated, then re-activated with the same config | Re-activation produces artifacts identical to the original activation |
| EC-003 | Lane config contains a floating-point tolerance value (e.g., `matchmaking_fairness_tolerance: 0.1`) | Artifacts are still bitwise-identical across runs; floating-point values in config are serialized canonically |
| EC-004 | Two different games with identical genre profiles but different game specs | Their lane artifacts may differ (different game content feeds different rating contracts, etc.); idempotency is per-game-spec, not cross-game |
