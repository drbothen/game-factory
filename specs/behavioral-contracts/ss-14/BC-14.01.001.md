# BC-14.01.001: XR Adapter Manifest Schema Validation

## Description

The XR adapter seam accepts an `xr-adapter` manifest that declares the XR backend,
engine binding, OpenXR version, and per-capability fidelity grades. Before any XR-related
processing occurs, the manifest must pass structural schema validation. This is the
`xr-adapter` equivalent of the engine adapter manifest validation in CAP-001/002. The
schema is the machine-checkable contract for the seam — it defines what a valid XR
adapter declaration looks like, regardless of whether an XR implementation is present.
Implementation is deferred; this BC concerns seam contract validity only.

## Preconditions

1. An `xr-adapter` manifest document exists.
2. The XR seam schema registry contains `xr-adapter-schema` at version 1.0 or later.
3. Schema validation is invoked as part of the pipeline's adapter registration step.

## Postconditions

1. **Valid manifest:** schema validation returns `valid: true`; the manifest is registered
   in the adapter registry with `status: registered` (not yet `conformance_passed` — that
   requires a conformance run against the actual XR runtime).
2. **Invalid manifest:** schema validation returns `valid: false` with a structured error
   list; the manifest is not registered; `E-XR-001` is emitted.
3. The schema-valid manifest is stored in the output artifact tree as the canonical record
   of the XR adapter seam contract for the game spec.

## Required Manifest Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `backend` | enum: `openxr` \| `visionos` | yes | XR API backend. `visionos` is a separate non-OpenXR target |
| `engine` | string | yes | Engine adapter ID this XR adapter rides (e.g., `unity`, `godot`) |
| `openxr_version` | string (semver) | yes (if backend=openxr) | OpenXR API version (e.g., `"1.1"`) |
| `conformance.suite` | string | yes (if backend=openxr) | Must be `"khronos-cts"` |
| `conformance.status` | enum: `wrap` \| `pending` \| `pass` \| `fail` | yes | CTS conformance state |
| `capabilities` | map<capability_id, capability_decl> | yes | Per-capability fidelity declarations |
| `deferred` | boolean | yes | `true` if this is a seam-only declaration (no runtime implementation) |

## Required Capability Declarations

| Capability ID | Required? | Valid fidelity values |
|--------------|-----------|----------------------|
| `stereo_render` | yes | `full`, `none` |
| `controllers` | yes | `full`, `partial`, `none` |
| `comfort_certify` | yes | `human-gated` (only valid value; see BC-14.01.003) |
| `hand_tracking` | no | `full`, `partial`, `none` |
| `eye_tracking` | no | `full`, `partial`, `none` |
| `passthrough` | no | `vendor`, `partial`, `none` |
| `foveation` | no | `full`, `partial`, `none` |
| `spatial_anchors` | no | `full`, `partial`, `none` |

## Invariants

1. `comfort_certify` capability must be present in every valid manifest; it may only have
   fidelity `human-gated` (BC-14.01.003 enforces this as a separate contract).
2. If `backend: openxr`, then `openxr_version` must be present and `conformance.suite`
   must be `khronos-cts`.
3. If `backend: visionos`, then `openxr_version` must be absent (BC-14.02.003 enforces
   the Apple Vision Pro non-OpenXR separation).
4. `engine` must reference a registered engine adapter ID; the XR seam is layered on top
   of the engine adapter.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Manifest declares `backend: visionos` with `openxr_version: "1.1"` | Schema validation fails (`E-XR-001`): visionOS manifests must not declare openxr_version |
| EC-002 | Manifest omits `comfort_certify` capability | Schema validation fails (`E-XR-001`): comfort_certify is required |
| EC-003 | Manifest sets `comfort_certify: {fidelity: full}` instead of `human-gated` | Schema validation fails (`E-XR-001`): comfort_certify must be human-gated (enforced at schema level) |
| EC-004 | `conformance.status: pass` on a `deferred: true` manifest | Schema validation accepts this (status reflects intent); a warning note is added that conformance cannot be verified for a deferred implementation |
| EC-005 | Unknown capability ID declared (e.g., `flying_saucers: {fidelity: full}`) | Schema validation fails (`E-XR-001`): unknown capability |
