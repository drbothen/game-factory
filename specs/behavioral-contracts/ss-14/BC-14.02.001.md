# BC-14.02.001: XR Performance Budget Schema

## Description

An `xr-perf-budget` is the XR-specific extension of the factory's existing
`perf-budget-contract`, adding dimensions that are specific to XR physiology and
runtime requirements. A well-formed `xr-perf-budget` must declare the target refresh
Hz, per-eye frame-time ceiling, reprojection-% ceiling, and motion-to-photon ceiling.
These are externally imposed by physiology and XR platforms — they are not design choices.
The budget is validated for internal consistency (e.g., per-eye frame-time ceiling must
be consistent with target refresh Hz). Frame-rate and reprojection metrics are on-device
gates (require a real runtime and HMD); stereo-render structural checks may run on a
software runtime (e.g., Monado) for headless CI.

## Preconditions

1. An XR adapter manifest has been registered (BC-14.01.001).
2. The game spec includes a `xr-perf-budget` declaration.
3. The budget is being validated before any XR perf gate runs.

## Postconditions

1. A validated `xr-perf-budget` artifact is generated containing:
   - `target_refresh_hz`: integer from the allowed set (72, 80, 90, 96, 100, 120).
   - `per_eye_frame_time_ceiling_ms`: computed from `1000 / target_refresh_hz` floored
     (e.g., 90 Hz → ≤11.11 ms per eye).
   - `reprojection_pct_ceiling`: percentage (0–100); a declared acceptable level of
     reprojected/dropped frames (recommended: ≤5% for Comfortable rating).
   - `motion_to_photon_ceiling_ms`: positive number (industry consensus: ≤20 ms to avoid
     sickness; values >20 ms trigger a warning).
   - `foveation_config`: optional; declares `kind` (fixed or eye_tracked) and expected
     GPU savings.
   - `measurement_method`: `on_device` (for frame-time/reprojection) or `headless_cts`
     (for stereo-render structural checks).
2. If `motion_to_photon_ceiling_ms > 20`: `W-XR-001` warning emitted (above industry
   comfort consensus; will likely result in Moderate or Intense comfort rating).
3. Internal consistency check: `per_eye_frame_time_ceiling_ms ≤ 1000 / target_refresh_hz`;
   if violated, `E-XR-004` is emitted.

## Platform-Specific Targets (primary-source verified, June 2026)

| Platform | Minimum fps | Frame-time ceiling | Refresh Hz options | Method |
|---------|------------|-------------------|-------------------|--------|
| Meta Quest (VRC.Quest.Performance.1) | 60 fps (30 fps with AppSW) | ≤16.67 ms at 60 Hz | 72/80/90/96/100/120 | OVR Metrics |
| SteamVR | Runtime-managed (no hard floor; Async Reprojection as fallback) | Runtime-adaptive | Varies by headset | Runtime stats |
| PSVR2 | 90–120 Hz expected [UNVERIFIED beyond public hardware specs] | ≤11.11 ms at 90 Hz | 90, 120 | NDA-gated TRC |

## Invariants

1. `target_refresh_hz` must be from the allowed set: {72, 80, 90, 96, 100, 120}. No
   arbitrary values permitted.
2. `motion_to_photon_ceiling_ms` must be > 0. Values ≤ 0 are rejected with `E-XR-004`.
3. On-device gates (frame-time, reprojection) may not be substituted by headless
   estimation; they require real hardware. This is declared in `measurement_method`.
4. The `xr-perf-budget` extends, never replaces, the flat-screen `perf-budget-contract`.
   Both must be present when XR is declared.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | `target_refresh_hz: 60` (below minimum for Meta Quest Comfortable rating) | Valid schema; `W-XR-002` warning: below 72 Hz targets may not meet comfort requirements on all platforms |
| EC-002 | `motion_to_photon_ceiling_ms: 25` | Schema valid; `W-XR-001`: above 20 ms consensus; comfort impact noted |
| EC-003 | `per_eye_frame_time_ceiling_ms` explicitly set to a value inconsistent with Hz (e.g., `90 Hz` but `frame_time: 20 ms`) | `E-XR-004`: inconsistent (20 ms > 11.11 ms ceiling for 90 Hz) |
| EC-004 | `foveation_config: {kind: eye_tracked}` declared on a headset without eye-tracking | Budget schema valid; runtime will degrade to FFR; `W-XR-003` advisory |
| EC-005 | `measurement_method: headless_cts` for frame-time gate | `E-XR-005`: frame-time measurement requires on-device method |
