# BC-14.02.002: XR Comfort Spec Schema — Locomotion, Vignette, Candidate Rating, Human-Gated Playtest Gate

## Description

An `xr-comfort-spec` is the document that prepares the input bundle for the
human-gated XR comfort playtest (BC-14.01.003). It declares the locomotion type(s)
used in the game, vignette configuration for artificial-turn comfort, a machine-derived
candidate comfort rating (labeled `heuristic_estimate`), and the human-gated playtest
gate that must be satisfied before the shipping comfort rating is finalized. The
`xr-comfort-spec` is a required artifact whenever an XR adapter is registered; it is
the structured input that the cert-owner uses during headset QA. It does not replace
the human gate — it stages it.

## Preconditions

1. An XR adapter manifest has passed schema validation (BC-14.01.001).
2. The `xr-comfort-spec` artifact is being authored or validated.
3. The game spec has declared at least one locomotion type.

## Postconditions

1. A validated `xr-comfort-spec` artifact is generated containing:
   - `locomotion_types`: one or more declared locomotion types (see Locomotion Types table).
   - `vignette_config`: for any locomotion type that involves artificial motion (teleport
     excepted), a vignette config is recommended; the schema accepts `enabled: true/false`
     and `onset_threshold_ms: <number>`.
   - `candidate_comfort_rating`: machine-derived estimate based on locomotion types and
     vignette config, labeled `heuristic_estimate: true`. This is NOT the shipping rating.
   - `playtest_gate`: object that records the status of the human-gated playtest:
     `status: pending | in_progress | complete`; `cert_owner: <role>`; `signed_off: false`
     initially.
2. The `playtest_gate.signed_off` field may only be set to `true` by a human cert-owner;
   any automated attempt to set it to `true` is blocked per DI-006 (BC-14.01.003).
3. The shipping comfort rating is the value in `playtest_gate.shipping_rating` (set by
   the human cert-owner), not `candidate_comfort_rating`.

## Locomotion Types and Comfort Heuristic Table

| Locomotion Type | Identifier | Typical Comfort Pressure | Recommended Vignette |
|----------------|------------|-------------------------|---------------------|
| Teleport | `teleport` | Low (minimal vestibular conflict) | Not required |
| Room-scale (physical) | `room_scale` | Low (real movement) | Not required |
| Smooth locomotion (joystick) | `smooth_locomotion` | High (artificial movement) | Strongly recommended |
| Snap turn | `snap_turn` | Low–medium | Not required |
| Smooth turn | `smooth_turn` | Medium–high | Recommended |
| Rail / on-rails | `on_rails` | Medium (user-driven vs scripted) | Recommended |
| Vehicle | `vehicle` | Medium–high (enclosure helps) | Context-dependent |
| Flying | `flying` | High (no ground reference) | Strongly recommended |
| Sprint / dash | `sprint_dash` | High | Strongly recommended |

## Candidate Comfort Rating Heuristic (informational only, NOT shipping rating)

The machine-derived candidate comfort rating is computed as follows (heuristic only):

| Conditions | Candidate Rating |
|------------|-----------------|
| Only `teleport` and/or `room_scale`; no artificial motion | `comfortable` |
| `snap_turn` present; no smooth locomotion | `comfortable` |
| `smooth_locomotion` or `smooth_turn` present; vignette enabled | `moderate` |
| `smooth_locomotion` or `smooth_turn` present; no vignette | `intense` |
| `flying` or `sprint_dash` present regardless of vignette | `intense` |

The output artifact includes `candidate_comfort_rating: {value: <rating>, heuristic_estimate: true}`.
The `heuristic_estimate: true` flag is mandatory. Omitting it is `E-XR-006`.

## Invariants

1. `locomotion_types` must contain at least one declared type. An empty array is rejected
   with `E-XR-006`.
2. `candidate_comfort_rating` must always carry `heuristic_estimate: true`. A spec that
   omits this field or sets it to `false` is rejected with `E-XR-006`.
3. `playtest_gate.signed_off` starts as `false`. Pipeline tooling may not set it to `true`
   (DI-006; BC-14.01.003).
4. Shipping comfort rating is ONLY the human-provided `playtest_gate.shipping_rating`.
5. A game with `smooth_locomotion` and no vignette config emits `W-XR-004`: smooth
   locomotion without vignette is likely to generate Intense comfort rating on playtest.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | `locomotion_types: []` | `E-XR-006`: at least one locomotion type required |
| EC-002 | `candidate_comfort_rating: {value: comfortable, heuristic_estimate: false}` | `E-XR-006`: heuristic_estimate must be true |
| EC-003 | `candidate_comfort_rating` field omitted | `E-XR-006`: field required in comfort spec |
| EC-004 | `smooth_locomotion` declared; `vignette_config.enabled: false` | Valid schema; `W-XR-004` warning: smooth locomotion without vignette is high sickness risk |
| EC-005 | `playtest_gate.signed_off: true` set by automated tooling | Blocked per DI-006; `E-XR-001`; pipeline gate remains open |
| EC-006 | Deferred XR adapter (`deferred: true`); comfort spec authored in advance | Valid; `playtest_gate.status: pending` with note that playtest activates when implementation ships |
| EC-007 | Multiple locomotion types (e.g., `teleport + smooth_locomotion`) | Valid; worst-case heuristic wins: candidate = `intense` or `moderate` per table |
| EC-008 | `locomotion_types: [unknown_type]` | `E-XR-006`: unknown locomotion type identifier |
