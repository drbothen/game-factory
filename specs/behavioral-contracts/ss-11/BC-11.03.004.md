# BC-11.03.004: Forbidden Dark Pattern — Minor Loot Box / Gacha Access (DP-008)

## Description

Defines the machine-checkable assertion that gacha mechanics and loot boxes
are inaccessible to minor (under-18) users unless the ethics contract explicitly
declares minor protections that comply with FTC COPPA 2025 (effective 22 Apr
2026), PEGI 16 minimum for paid random items (effective Jun 2026), and Belgium's
gambling law classification. This is DP-008. The assertion checks that
`minor_protection.no_loot_box_for_minors == true` in the active ethics contract
whenever a `gacha-spec` artifact is present, and that the implementation spec
declares an age-gate or parental-consent gate before any paid random mechanic
is accessible.

## Preconditions

1. A `gacha-spec` artifact exists for this game_id with `paid_pulls_enabled: true`.
2. The `monetization-ethics-contract` is structurally valid (BC-11.01.001 PASS).
3. The game's target distribution platforms include at least one platform where
   COPPA or age-gating requirements apply (i.e., any non-adults-only platform).

## Postconditions

1. **COMPLIANT:** `ethics_contract.minor_protection.no_loot_box_for_minors == true`
   AND the UI/age-gate spec declares that the gacha purchase flow is gated
   behind an age verification or parental consent step before the first purchase.
2. **VIOLATION (no_loot_box_for_minors is false):** Error:
   `MINOR_LOOT_BOX_ACCESS_VIOLATION`. The ethics contract must set this field
   to `true` whenever gacha/paid random mechanics are present.
3. **VIOLATION (no age gate in spec):** `no_loot_box_for_minors == true` but
   the UI spec does not declare an age verification or parental-consent gate
   before the gacha purchase flow. Error:
   `MINOR_PROTECTION_UNIMPLEMENTED`. Policy is declared but no implementation
   spec exists to enforce it.
4. **REGULATORY FLAG:** PEGI 16 trigger is emitted as a compliance cross-reference
   to `content-descriptor-contract` whenever gacha is present. This is not a
   block; it is a mandatory annotation that the compliance pipeline (CAP-010)
   must process.

## Invariants

1. `minor_protection.no_loot_box_for_minors` defaults to `true` in the default
   ethics envelope and cannot be set to `false` in a custom contract without
   adversarial review AND legal human sign-off.
2. The age-gate implementation spec must declare the specific gate mechanism
   (e.g., `parental_consent_dialog`, `age_verification_third_party`,
   `platform_age_gate`). A generic "we will add an age gate" note is insufficient.
3. This BC is cross-referenced with the compliance pipeline (CAP-010). The
   PEGI 16 annotation produced here feeds into `content-descriptor-contract`
   → `ratings-submission-manifest`.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Game targets Belgium (where paid loot boxes are classified as gambling) | Separate `regional_restrictions` check fires. This BC fires in addition. Belgium-targeted games cannot permit paid gacha at all, so `gacha_permitted_in_belgium: false` should be in the ethics contract regional map. |
| EC-002 | Game is rated 18+ on all target platforms from launch | `minor_protection.no_loot_box_for_minors` is still required but may use the platform's own 18+ rating as the gate mechanism. The BC PASSES if the age gate is the 18+ platform gate. |
| EC-003 | Free gacha (no real-money or premium-currency purchase required) | DP-008 applies to paid random mechanics only. Free gacha is exempt from the minor-access block but a warning recommends voluntary restrictions for best practice. |
| EC-004 | Parental control API declared but not yet integrated | VIOLATION: `MINOR_PROTECTION_UNIMPLEMENTED`. Declaration without implementation spec is insufficient. |
| EC-005 | Game declares `child_directed: false` in privacy config | Still does not exempt the game from the age-gate requirement on gacha. COPPA applies based on audience characteristics, not just the `child_directed` flag. |
