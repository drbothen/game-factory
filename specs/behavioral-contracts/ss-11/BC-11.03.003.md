# BC-11.03.003: Forbidden Dark Pattern — Loss-Triggered Purchase Prompt (DP-003)

## Description

Defines the machine-checkable assertion that no purchase prompt, spend
recommendation, or "offer" UI event is triggered within a declared proximity
window of a loss event (game over, run end, match defeat, death, fail state).
This is DP-003: exploiting emotional distress after failure. It is grounded
in the DiGRA dark patterns taxonomy for monetized games, the FTC v. Epic
findings, and the broader literature on exploitative timing of purchase prompts.
The assertion is evaluated against the UI/event spec: specifically, the event
graph's time-ordering constraints between purchase prompt events and loss events.

## Preconditions

1. A UI event spec or game-event graph artifact exists for this game_id.
2. The game declares at least one "loss event" type in its event taxonomy
   (e.g., `event_type: "game_over"`, `"run_fail"`, `"match_defeat"`,
   `"player_death"`).
3. `monetization-ethics-contract.pressure_bounds.no_loss_triggered_offers == true`
   (default envelope applies this as default).
4. The purchase prompt event types are identified in the event taxonomy
   (`event_type: "purchase_prompt"`, `"spend_recommendation"`, `"offer_popup"`).

## Postconditions

1. **PASS:** No purchase prompt event is scheduled to fire within
   `pressure_bounds.loss_trigger_proximity_window_ms` of any declared loss
   event in the event graph. The default window is 10,000ms (10 seconds).
   A longer window may be declared in the ethics contract.
2. **VIOLATION:** A purchase prompt event fires within the proximity window of
   a loss event in the event graph specification. Error: **E-ETH-012**
   (`error.data.reason: LOSS_TRIGGERED_PURCHASE_PROMPT_DETECTED`) with the
   loss event type, prompt event type, and measured minimum time gap.
3. **UNVERIFIABLE:** The event graph does not have time-ordering constraints
   specified (events are not ordered). Warning:
   `LOSS_TRIGGER_CHECK_REQUIRES_EVENT_ORDERING`. The check cannot complete;
   the adversarial review (A-02) must manually verify this constraint.
4. **EXEMPT:** Ethics contract explicitly permits loss-triggered offers (e.g.,
   a "continue?" prompt after a run-based game) AND `human_sign_off_ref` is
   non-null for this specific exemption. Permitted with warning that adversarial
   review must scrutinize this exemption under A-02.

## Invariants

1. The default proximity window is 10 seconds post-loss. This is a conservative
   default. Studios may extend it (e.g., 30 seconds) in the ethics contract;
   they may not reduce it below 5 seconds without adversarial review.
2. "Continue?" prompts (roguelike death revive, life system replenishment) are
   NOT automatically exempt. The `continue_prompt_permitted` flag in the ethics
   contract must explicitly permit them. This is because continue prompts after
   death are a documented dark pattern (DP-003 variant).
3. The check applies to the event SPECIFICATION, not runtime behavior. The
   factory validates the declared event ordering at spec time. Runtime
   enforcement is the responsibility of the implementation; the factory can
   only validate what is declared.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Roguelike death → "Continue for 100 gems?" prompt immediately (0ms gap) | VIOLATION: E-ETH-012 (`LOSS_TRIGGERED_PURCHASE_PROMPT_DETECTED`), gap=0ms, threshold=10000ms. Unless `continue_prompt_permitted: true` and adversarially reviewed. |
| EC-002 | Match defeat → 5-second victory screen → "Buy battle pass" banner (5000ms gap) | VIOLATION: E-ETH-012, 5000ms < 10000ms default window. |
| EC-003 | Match defeat → 15-second result screen → "Buy battle pass" banner (15000ms gap) | PASS: 15000ms > 10000ms default window. |
| EC-004 | Event graph has no time-ordering constraints | Warning: `LOSS_TRIGGER_CHECK_REQUIRES_EVENT_ORDERING`. Adversarial review must manually check. |
| EC-005 | Purchase prompt fires on game launch (not near any loss event) | PASS for this BC. (Prompts on launch have separate ethics scrutiny but are outside the loss-trigger window.) |
| EC-006 | Ethics contract sets `loss_trigger_proximity_window_ms: 3000` (3 seconds) | Warning: `LOSS_PROXIMITY_WINDOW_BELOW_MINIMUM`. Window cannot be below 5000ms without adversarial review. If adversarial review has been completed and this exemption is noted, PASS with warning retained in record. |
