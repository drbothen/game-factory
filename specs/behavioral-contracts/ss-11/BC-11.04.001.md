# BC-11.04.001: Gacha EV and Pity Correctness (Ethics-Bounded)

## Description

Defines machine-checkable assertions over gacha pull mathematics: expected
value per pull, worst-case cost-to-target (P(fail to obtain target item after
N pulls)), and pity mechanism correctness (the guarantee actually fires at
the declared threshold). These are verified against the `gacha-spec` artifact
using a closed-form calculation and/or a Monte-Carlo simulation. The
"ethics-bounded" qualifier means the computed EV and cost-to-target are also
compared against the bounds declared in the `monetization-ethics-contract`.
This BC is the primary tie-point between CAP-011 ethics enforcement and the
CAP-006 simulation verification substrate for gacha mechanics.

## Preconditions

1. A `gacha-spec` artifact exists with `paid_pulls_enabled: true`.
2. `published_odds` is present and complete (BC-11.03.001 PASS).
3. `monetization-ethics-contract` is structurally valid and declares
   `max_expected_cost_to_target_usd` and `pity_guaranteed: true/false`.
4. The economy simulation has access to the `gacha-spec`'s item pools,
   probabilities, pity thresholds, and pull cost in premium currency
   (with real-money cost derivable from `pricing-matrix`).

## Postconditions

1. **EV COMPUTED AND WITHIN BOUNDS:**
   - `EV_per_pull_usd` is computed as: sum over all items of
     `P(item) × declared_value(item)` converted to USD via pricing-matrix.
   - `expected_cost_to_target_usd` = `pull_cost_usd / P(target)` (base rate,
     without pity; pity-adjusted calculation also provided).
   - Both values are within the bounds declared in the ethics contract.
   - If `P(target_base) < 0.01` (less than 1% base rate), the ethics contract
     must explicitly declare `max_expected_cost_to_target_usd` for this mechanic.
2. **PITY CORRECTNESS:**
   - If `gacha-spec` declares a pity counter (guaranteed item at pull N),
     the simulation verifies: P(not obtaining target after N pulls given pity)
     = 0.0 exactly (hard guarantee).
   - If `gacha-spec` declares soft pity (probability increase starting at pull
     M), the simulation verifies: `P(pull ≤ M) < P(pull M+1) < ... < P(pity_N)`
     (monotonically increasing probability ramp).
3. **EV OUT OF ETHICS BOUNDS:** `expected_cost_to_target_usd` exceeds
   `ethics_contract.max_expected_cost_to_target_usd`. Error:
   `GACHA_COST_TO_TARGET_EXCEEDS_ETHICS_BOUND`: computed value vs. declared
   maximum.
4. **PITY INCORRECT:** Hard pity fires at the wrong pull number, or does not
   fire at all. Error: `GACHA_PITY_MECHANISM_INCORRECT`: expected fire at
   pull N, observed behavior in simulation.
5. **PITY UNVERIFIABLE:** Pity spec is declared but the simulation cannot
   verify it (spec is ambiguous). Warning: `GACHA_PITY_UNVERIFIABLE`.
   Adversarial review must manually check.

## Invariants

1. EV calculation uses the declared probabilities from `published_odds`, not
   an internal implementation value. If they differ, there is a disclosure
   accuracy problem (separate from this BC but flagged as a cross-reference
   to BC-11.03.001).
2. Cost-to-target is computed for the stated "target" which is the rarest
   declared item (or the featured banner item in a 50/50 mechanic). The ethics
   contract must name the target item class for the bound to be meaningful.
3. The Monte-Carlo simulation runs at minimum 1,000,000 simulated pull sequences
   to obtain statistically robust EV and pity-fire-rate estimates.
4. The worst-case cost is `P(fail N times) × (pull_cost × N) + (pull_cost × N_pity)`
   where N_pity is the hard-pity threshold. This is the maximum any player
   will spend to obtain a specific item and must be bounded by the ethics
   contract.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Gacha has 0.6% base rate for 5-star; hard pity at 90 pulls; pull cost = $2.00 | EV per pull = 0.006 × item_value; worst-case cost = 90 × $2 = $180. Ethics contract must declare `max_expected_cost_to_target_usd >= 180`. If contract says 150, FAIL. |
| EC-002 | 50/50 mechanic: first 5-star is 50% chance to be featured; if not, next 5-star is guaranteed featured | Compute expected pulls to guaranteed featured 5-star: ~180 base + pity. Ethics contract must bound this. Worst-case = 2 × hard_pity = 180 pulls = $360. |
| EC-003 | Soft pity ramp declared but monotonicity not strictly increasing at one step | FAIL: `GACHA_PITY_MECHANISM_INCORRECT`. Soft pity must be monotonically increasing from the declared start pull. |
| EC-004 | Pity counter resets on banner change before hard pity fires | This must be declared in `gacha-spec`. If it is, the worst-case cost-to-target is computed per-banner. If undeclared, flag as `GACHA_PITY_RESET_UNDECLARED`. |
| EC-005 | `ethics_contract.max_expected_cost_to_target_usd` is absent when `P(target_base) < 0.01` | Structurally invalid per this BC's preconditions. Pipeline returns `ETHICS_CONTRACT_GACHA_BOUND_REQUIRED`. |
| EC-006 | Gacha item values cannot be converted to USD (no declared USD value, only "game power") | EV is computed in pull-count units, not USD. Cost-to-target is in USD (pull cost × expected pulls). The ethics contract bound should be in USD for the `max_expected_cost_to_target_usd` field. |

## Canonical Test Vectors

| Input | Expected Output | Category |
|-------|----------------|----------|
| 1% base rate; hard pity 100 pulls; $1/pull; ethics bound $200 | EV computed; worst-case = $100; within $200 bound; PASS | happy-path |
| 1% base rate; hard pity 100 pulls; $1/pull; ethics bound $80 | `GACHA_COST_TO_TARGET_EXCEEDS_ETHICS_BOUND`: worst_case=$100, bound=$80 | error (over bound) |
| Soft pity declared at pull 50 but probability at pull 51 is lower than pull 50 | `GACHA_PITY_MECHANISM_INCORRECT`: monotonicity violation at pull 51 | error (pity) |
| Hard pity at 90; simulation shows pity fires at pull 92 in some seeds | `GACHA_PITY_MECHANISM_INCORRECT`: expected pull 90, fires at 92 | error (pity correctness) |
