# BC-11.02.001: No Unconstrained LTV Optimization Objective (Fail-Closed for All Agents)

## Description

Defines the CONSTRAINED-OPTIMIZATION rule as a machine-checkable assertion
that is evaluated cross-cuttingly across ALL pipeline agents, not just the
monetization-designer. No pipeline agent — economy-designer, economy-balancer,
liveops-sre, or any auto-tuning hook — may declare `maximize_ltv_unconstrained`,
`maximize_arpu_unconstrained`, or `maximize_engagement_unconstrained` as an
optimization objective. The check runs at ethics-gate evaluation and on every
agent config mutation. This is the machine-enforceable form of DI-005.

## Preconditions

1. At least one agent config exists in the pipeline for this game_id.
2. The factory pipeline has reached the constrained-optimization check
   (triggered on every agent config creation or mutation).

## Postconditions

1. **PASS:** All pipeline agent configs have `optimization_objective` fields
   that either: (a) are absent (no optimization declared), (b) declare a
   constrained objective with `constraints` non-empty, or (c) reference the
   active `monetization-ethics-contract` as their constraint source via
   `constraint_source_ref`.
2. **FAIL (unconstrained objective):** Any agent config contains one of:
   - `optimization_objective: "maximize_ltv_unconstrained"`
   - `optimization_objective: "maximize_arpu_unconstrained"`
   - `optimization_objective: "maximize_engagement_unconstrained"`
   - `optimization_objective.unconstrained: true`
   Pipeline FAILS with `UNCONSTRAINED_OPTIMIZATION_DETECTED`. The specific
   agent_id and field path are included in the error. This is a factory defect.
3. **FAIL (objective without constraint reference):** Agent config declares
   an objective but `constraints` is empty AND `constraint_source_ref` is
   null. Pipeline FAILS with `OPTIMIZATION_OBJECTIVE_WITHOUT_CONSTRAINTS`.

## Invariants

1. This check fires on EVERY agent config mutation, not just at convergence
   time. An unconstrained objective cannot be introduced mid-pipeline and
   persist until convergence.
2. The hook runs at the same priority as the `monetization-ethics-present`
   hook. Both are P0 hooks that cannot be disabled or bypassed.
3. An agent config that references the active `monetization-ethics-contract`
   as `constraint_source_ref` inherits the contract's constraints. This is
   the recommended pattern for agent configs — inherit rather than redeclare.
4. "Engagement optimization" is treated identically to LTV optimization for
   the purposes of this rule. Engagement-maximization without declared
   constraints is the mechanism behind EOMM-class dark patterns (RECONCILIATION
   §12 R-010); treating it as exempt would be a policy hole.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | `economy-designer` agent config has `optimization_objective` absent | PASS: absent objective = no unconstrained maximization declared |
| EC-002 | `economy-balancer` uses a Machinations-style optimizer with default objective "maximize_player_engagement" | FAIL: `UNCONSTRAINED_OPTIMIZATION_DETECTED` unless the agent config wraps the optimizer call with explicit constraints from the ethics contract. Machinations Balancer must be configured with ethics-contract constraints before it is invoked. |
| EC-003 | `liveops-sre` A/B framework has `optimization_objective: "maximize_revenue"` with `constraints: [{"type": "max_gini", "threshold": 0.70}]` | PASS: constrained objective with non-empty constraints. The word "maximize" in an objective name does not trigger the check; the check is on the `unconstrained` semantic. |
| EC-004 | Agent config uses `constraint_source_ref` pointing to an expired ethics contract (game has a new contract version) | FAIL: `CONSTRAINT_SOURCE_REF_STALE`. Agent config must be updated to reference the current contract. |
| EC-005 | Agent config uses a proxy metric like "maximize_session_length" | This is not automatically blocked by this BC. However, if `monetization-ethics-contract.forbidden_patterns` includes `escalating_session_pressure` (DP-003 adjacent), the dark-pattern check (BC-11.03.003) would flag it. This BC only checks objective field values, not proxy semantics. |
| EC-006 | No monetization present in the game (`archetype: "premium"`, no IAP) | Check still fires on any agent config that declares an optimization objective. Even premium games may not have unconstrained engagement objectives (R-010 applies to matchmaking, not just monetization). |
