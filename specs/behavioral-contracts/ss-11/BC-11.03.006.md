# BC-11.03.006: Forbidden Dark Pattern — Predatory Vulnerability Targeting / Whale Hunting (DP-007)

## Description

Defines the machine-checkable enforcement of dark pattern DP-007: any
`segmentation-ltv-spec` artifact that contains an offer-escalation rule conditioned
on a vulnerability proxy (a data signal that functions as a behavioral indicator of
psychological susceptibility to financial pressure — e.g., inferred loss sensitivity,
recent session-loss streak, late-night active session, self-reported financial stress
flag, accelerating consecutive purchase velocity, recency-weighted churn-risk score)
is a prohibited predatory-targeting pattern. This pattern constitutes "whale hunting":
deliberately identifying players in psychologically vulnerable states and escalating
commercial pressure against them. It is prohibited under EU DSA Article 28(b)(i)
(Dark Patterns Regulation) and creates significant FTC Section 5 exposure consistent
with the FTC v. Epic settlement ($245M, Mar 2023). This BC enforces the structural
prohibition at the `segmentation-ltv-spec` artifact layer.

## Preconditions

1. A `segmentation-ltv-spec` artifact exists for this game_id (i.e., the game uses
   any form of player behavioral segmentation for monetization targeting).
2. The `monetization-ethics-contract` is structurally valid (BC-11.01.001 PASS).
3. The `segmentation-ltv-spec` schema version is declared.

## Postconditions

1. **COMPLIANT:** The `segmentation-ltv-spec` contains no offer-escalation rule
   (no rule of the form `if <vulnerability_proxy_signal> then escalate_offer_tier`
   or equivalent logic). Offer targeting rules are based only on non-vulnerability
   signals: purchase history, content preferences, platform, region, session depth.
2. **VIOLATION — explicit vulnerability proxy:** Any rule in the spec's
   `escalation_rules[]` array has a `condition` field that references a vulnerability
   proxy from the declared blocklist (see Invariants §1). Error: `E-ETH-009`
   (`PREDATORY_TARGETING_VULNERABILITY_PROXY`): the specific rule ID, the proxy
   signal name, and the blocked-signal category are included in the error payload.
   Pipeline BLOCKED.
3. **VIOLATION — computed vulnerability proxy:** The spec contains a derived feature
   or composite score that is computed as a weighted combination of blocked signals
   even if the composite score is given an innocuous name. Any composite score that
   references two or more blocked signals in its computation formula is treated as a
   vulnerability proxy. Error: `E-ETH-009` with `category: computed_proxy`.
4. **REQUIRES ADVERSARIAL REVIEW (ambiguous signal):** A signal is present that is
   not on the blocked list but whose name or description contains terms semantically
   proxying vulnerability (e.g., "frustration_score", "engagement_desperation_index").
   The factory emits a warning `VULNERABILITY_PROXY_SUSPECTED` and flags the spec for
   adversarial review. The `D-ETHICS` convergence dimension is set to AMBER until the
   review is complete.
5. **NO SEGMENTATION SPEC (permissive case):** No `segmentation-ltv-spec` artifact
   exists. This check passes trivially — the pattern cannot be present if there is
   no segmentation config.

## Invariants

1. **Blocked vulnerability proxy signals (exhaustive list; additions require ADR):**
   - `session_loss_streak_last_N` or equivalent consecutive-loss counters (N ≥ 3)
   - `late_night_session` indicator (sessions between 23:00–05:00 local time)
   - `self_reported_stress_flag` or any ingested self-report indicating financial
     or emotional difficulty
   - `churn_risk_score_high` or recency-weighted churn-risk score in the top quartile
   - `accelerating_purchase_velocity` (purchases per session increasing
     monotonically over last K sessions; K ≥ 3)
   - Any signal derived from advertising SDK data that proxies financial vulnerability
     (e.g., credit-score-proxy tiers from ad attribution partners)
   - Any signal labeled or documented as identifying "whales at risk of churning"
2. The `segmentation-ltv-spec` may not contain an `offer_escalation_on_vulnerability`
   boolean set to `true` (explicit opt-in to predatory targeting).
3. Offer escalation based on voluntary self-reported engagement level (e.g., "hardcore
   gamer" self-identification selected in settings) is NOT a vulnerability proxy and
   is permitted. The distinction is: self-identification in a non-pressured context
   vs. behavioral inference of psychological susceptibility.
4. This BC does not prohibit LTV-based segmentation per se — only the subset that
   conditions escalation on vulnerability indicators. Segmenting players by content
   preferences, platform, or playtime is unaffected.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | `segmentation-ltv-spec` uses only content-preference and platform signals for offer targeting | PASS: no vulnerability proxies |
| EC-002 | Spec contains rule: `if session_loss_streak_last_5 >= 3 then increase_offer_tier_by 2` | VIOLATION: `E-ETH-009`; `session_loss_streak_last_5` is a blocked signal |
| EC-003 | Spec computes a `desperation_index = 0.4 * churn_risk_score + 0.6 * session_loss_streak_last_3` | VIOLATION: composite score references two blocked signals; treated as computed vulnerability proxy |
| EC-004 | Spec contains rule: `if frustration_score > 0.7 then show_limited_time_offer` | REQUIRES ADVERSARIAL REVIEW: `frustration_score` is not on the explicit blocklist but semantically proxies vulnerability; flagged AMBER |
| EC-005 | Spec uses `days_since_last_purchase` (recency signal, not vulnerability) to target lapsed players | PASS: recency-based re-engagement is a standard marketing pattern; not a vulnerability proxy |
| EC-006 | Game has no `segmentation-ltv-spec` (premium-only game, no segmentation) | PASS-TRIVIAL: no spec to check |
| EC-007 | Spec rule: `if player.self_identified_as == "hardcore"` then show advanced DLC | PASS: voluntary self-identification in settings, not behavioral inference of susceptibility |
