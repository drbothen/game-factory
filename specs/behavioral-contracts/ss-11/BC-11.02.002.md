# BC-11.02.002: Constrained-Optimization Invariant — Economy Spine Propagation

## Description

Defines how the ethics contract's declared constraints must propagate into
the `live-economy-balance-contract` (a CAP-005 artifact) and become
machine-checkable assertions verified by the economy simulation (a CAP-006
verification substrate). The key insight from the research corpus is that
the ethics contract does not float free: every constraint it declares must
map to at least one concrete assertion in the economy simulation that the
CAP-006 infrastructure can evaluate. This BC defines the propagation contract
between CAP-011 (ethics) and CAP-006 (simulation verification).

## Preconditions

1. A structurally valid `monetization-ethics-contract` exists (BC-11.01.001
   PASS) with at least one constraint declared.
2. A `live-economy-balance-contract` artifact exists for this game (produced
   by the economy-designer or economy-balancer agent, CAP-005).
3. The economy simulation (Machinations-style, Machinations-wrap) is available
   and can evaluate the assertions.

## Postconditions

1. **PROPAGATED:** For each constraint in `ethics_contract.constraints`, a
   corresponding assertion exists in `live-economy-balance-contract.assertions`.
   The assertion references the constraint by `constraint_id`. At minimum:
   - `max_p2w_power_gap_percent` constraint → assertion verifying combat-power
     distribution across spend tiers does not exceed declared gap
   - `max_spend_concentration_gini` constraint → assertion verifying Gini
     coefficient on simulated spend distribution ≤ threshold
   - `no_progression_deadlock_without_spend` constraint →
     assertion in BC-11.02.003
   - `max_expected_cost_to_target` constraint (if gacha present) →
     assertion in BC-11.04.001
2. **SIM PASS:** The economy simulation runs the assertions for all player
   archetype distributions declared in the `sink-faucet-model` and all
   assertions PASS.
3. **ASSERTION MISSING:** A constraint exists in the ethics contract but no
   corresponding assertion exists in the economy balance contract. Pipeline
   returns `ETHICS_CONSTRAINT_WITHOUT_ECONOMY_ASSERTION` with the specific
   constraint_id. This is a gap, not a pass.
4. **ASSERTION FAIL:** A sim assertion runs and FAILS (e.g., pay-to-win gap
   exceeds declared maximum). Pipeline returns `ECONOMY_ETHICS_ASSERTION_FAIL`
   with the assertion_id, measured value, and threshold. This blocks convergence
   dim-10.

## Invariants

1. There is a required 1:1 mapping between each numeric ethics constraint
   and at least one economy-sim assertion. A constraint without an assertion
   is unverified, which violates DI-012 (every ContractArtifact must have a
   declared validation method — and "check the sim" is the validation method
   for these constraints).
2. The economy simulation must use all player archetype distributions declared
   in the `sink-faucet-model`, not just the average case. Passing for the
   average payer while failing for the whale archetype is not acceptable.
3. The mapping is maintained by the `economy-balancer` agent. When the ethics
   contract is updated, the agent must re-evaluate whether the mapped
   assertions still cover all constraints.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Ethics contract has `max_p2w_power_gap_percent: 0` (cosmetics-only) | Economy sim asserts that NO spend tier has any mechanical advantage in combat. A power gap of any magnitude fails the assertion. |
| EC-002 | `sink-faucet-model` not yet produced (economy design incomplete) | `ECONOMY_ASSERTIONS_CANNOT_BE_EVALUATED`: precondition not met. Assertions blocked until sink-faucet-model exists. Convergence dim-10 remains BLOCKED. |
| EC-003 | Ethics contract constraint is qualitative (e.g., "feel fair to players") | Qualitative constraints cannot produce economy-sim assertions. This is treated as a contract authoring error: `QUALITATIVE_CONSTRAINT_NOT_MACHINE_CHECKABLE`. The constraint must be replaced with a numeric bound. |
| EC-004 | Constraint threshold is at the boundary (e.g., Gini = exactly 0.70 with threshold 0.70) | Boundary case: `<=` semantics. Gini == 0.70 is PASS. Gini == 0.701 is FAIL. The constraint must specify whether the bound is inclusive; default is inclusive (<=). |
| EC-005 | Economy sim is run over a synthetic player population (no live data) | Explicitly correct. The factory runs simulations over declared archetype distributions (casual/mid-core/hardcore/whale) per the `sink-faucet-model`. Real willingness-to-pay is not required pre-ship; the simulation is the pre-live validation. |
| EC-006 | Ethics contract updated to tighten constraints (lower P2W gap max) after initial sim pass | All economy assertions are re-evaluated against the tighter constraints. A previously passing assertion may now fail. The update is always backward-checked. |
