# BC-11.02.003: No-Progression-Deadlock-Without-Spend Invariant

## Description

Defines the machine-checkable assertion that no player archetype in the
declared player population reaches a progression deadlock (a state from which
further meaningful game progress is impossible without a real-money purchase)
unless the `monetization-ethics-contract` explicitly declares a
`progression_deadlock_by_design: true` flag AND a human has signed off on
that policy decision. This is the ethics contract's expression of the fairness
principle that free players must be able to experience the game without being
coerced into spending. It is verified against the economy simulation's
time-to-goal distribution for each player archetype.

## Preconditions

1. `live-economy-balance-contract` exists with `sink-faucet-model` populated.
2. `monetization-ethics-contract` has `no_progression_deadlock_without_spend`
   constraint declared (or the default envelope applies it as `true`).
3. Player archetype distributions are declared in `sink-faucet-model` (at
   minimum: `non_payer` and `casual_payer`).
4. The economy simulation can compute time-to-goal distributions per archetype.

## Postconditions

1. **PASS:** For every declared archetype where `spend_tier == 0` (non-payer),
   the economy simulation finds at least one valid progression path through
   every declared progression gate without requiring a real-money transaction.
   Time-to-goal may be longer for non-payers but must be finite and reachable.
2. **FAIL (hard deadlock):** The `non_payer` archetype reaches a state S from
   which the only transitions that lead to game-complete require `spend > 0`.
   Error: **E-ETH-005** (`error.data.reason: PROGRESSION_DEADLOCK_DETECTED`)
   with state S, archetype, and the spend-required transitions listed.
3. **EXEMPTED (by-design):** `ethics_contract.progression_deadlock_by_design
   == true` AND `human_sign_off_ref` is non-null. Pipeline records the
   exemption and passes. The exemption must be explicitly named in the
   adversarial review (A-02 check).
4. **PENDING (simulation incomplete):** `sink-faucet-model` archetype
   distributions do not include a `non_payer` archetype. Error:
   `NON_PAYER_ARCHETYPE_MISSING`. The model must declare at least a free player.

## Invariants

1. A `non_payer` archetype must always be present in the `sink-faucet-model`
   when monetization is active. The factory cannot reason about progression
   fairness without a free-player archetype.
2. "Infinite grind" (time-to-goal is extremely long but finite) is not the
   same as deadlock. This BC only blocks hard deadlocks (spend is the ONLY
   path). Grind length relative to payer is a business decision declared in
   the ethics contract (e.g., `max_free_grind_multiplier: 5x`).
3. The exemption path (`progression_deadlock_by_design`) exists for games
   where a content gate behind a purchase is an intentional design — e.g.,
   premium DLC levels. The exemption must name the specific gates and must
   be adversarially reviewed.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Premium game with zero monetization | Invariant not applicable. Non-payer IS the only archetype. PASS trivially. |
| EC-002 | Cosmetics-only F2P where all content is free | All progression gates have free paths. PASS. |
| EC-003 | F2P where final boss requires a power-boosting IAP (hard P2W deadlock) | FAIL: E-ETH-005 (`PROGRESSION_DEADLOCK_DETECTED`). Boss encounter is a game-complete progression gate; IAP-only path violates the invariant. |
| EC-004 | F2P with a premium expansion (`$15 DLC`, 20 extra levels). Base 50 levels free. | Acceptable IF `progression_deadlock_by_design: true` explicitly covers only the DLC levels, AND base game is complete without DLC. Adversarial review checks that "complete" is meaningful without DLC. |
| EC-005 | Energy timer system where non-payers run out of energy and cannot play for 8 hours | NOT a hard deadlock (time-gated, not money-gated). But DP-002/DP-003 checks may still fire depending on implementation. |
| EC-006 | `max_free_grind_multiplier` declared as `100x` (non-payer needs 100× the sessions of a payer) | Not a deadlock. But this may be flagged as unreasonable grind in the adversarial review (A-02). This BC does not enforce a grind multiplier cap — that would be a separate ethics contract constraint. |
