# BC-15.11.001: Entitlement and Leaderboard Integrity — D-SEC Reference Contract

## Description

The online-services adapter's server-authority model for leaderboards and entitlements
is a concrete instantiation of the D-SEC convergence dimension governed by BC-7.11.002
(no-trust-client) and BC-7.11.008 (secure entitlement verification). This BC declares
the bridge contract: violations in the online-services leaderboard or entitlement path
MUST surface as D-SEC dimension signals, not as silent online-services errors. This
ensures that a cheated leaderboard submission or an entitlement bypass is treated as a
security dimension failure (blocking release convergence), not merely an operational
degradation. No new convergence dimension is created — D-SEC absorbs these signals.

**This BC does NOT duplicate the server-authority spine (BC-7.11.002, BC-7.11.008).
It declares the routing rule: online-services integrity failures → D-SEC.**

## Preconditions

1. A project declares `online_features: true` with non-`none` leaderboard or entitlement
   fidelity.
2. A server-authority violation occurs in the online-services path: either a tampered
   leaderboard score is accepted by the adapter, or a client-asserted entitlement is
   granted without server verification.
3. The D-SEC convergence dimension is being evaluated (BC-7.11.001).

## Postconditions

1. **PASS — no violations:** All leaderboard submissions are server-validated; all
   entitlement verifications query the authoritative store. D-SEC dimension receives
   GREEN signal from the online-services seam.
2. **FAIL — leaderboard trust-client violation detected:** A tampered score was accepted
   by the online-services adapter without server-side validation. This surfaces as:
   `E-CONV-006` (`D-SEC dimension non-green`) with detail
   `online-services: leaderboard trust-client violation — BC-7.11.002 violated in
   leaderboard path via online-services adapter '<targetId>'`.
3. **FAIL — entitlement trust-client violation detected:** A client assertion of
   entitlement ownership was honored without entitlement store verification. This surfaces
   as `E-CONV-006` with detail
   `online-services: entitlement trust-client violation — BC-7.11.008 violated in
   entitlement path via online-services adapter '<targetId>'`.
4. **ONLINE EXEMPTION:** `online_features: false` or `offlineProject: true`. D-SEC
   online-services check is INAPPLICABLE for leaderboard and entitlement sub-checks.
   D-SEC dimension is not blocked by this BC's scope.

## Invariants

1. Leaderboard and entitlement integrity violations ALWAYS surface through D-SEC, not
   through local error codes only. A local `E-OSVC-003` (ScoreRejectedByServer) is a
   positive outcome (server IS enforcing authority); D-SEC failure occurs only when the
   server FAILS to enforce authority.
2. D-SEC is the single convergence gate for security signals across all seams. The
   online-services seam must not create a parallel security convergence dimension.
3. The conformance suite (BC-15.08.001) includes server-authority test cases (part 4)
   precisely to catch these violations before production acceptance.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Server correctly rejects tampered score (E-OSVC-003) | PASS: D-SEC receives positive signal — authority IS being enforced |
| EC-002 | Server accepts tampered score without validation | FAIL: E-CONV-006 D-SEC non-green; release blocked |
| EC-003 | Server grants entitlement based on client assertion (no store query) | FAIL: E-CONV-006 D-SEC non-green |
| EC-004 | Offline project (`online_features: false`) | INAPPLICABLE: D-SEC online-services check skipped for this project |
| EC-005 | Conformance suite part 4 (server-authority test) fails | E-CONF-004 acceptance gate; adapter not accepted; D-SEC not reached |
