# BC-15.10.001: Online-Services Graceful Degradation — CapabilityUnsupported for None-Fidelity Capabilities

## Description

When the online-services adapter declares `fidelity: none` for any capability, calling
that capability's JSON-RPC method must return `CapabilityUnsupported` (E-EAP-002) — not
crash, not silently succeed, and not return a stale or fabricated result. The factory
core must catch `CapabilityUnsupported` from any online capability call and degrade the
affected convergence signal without halting the pipeline. This is the online-services
instantiation of the base protocol graceful-degradation contract (BC-1.13.001 and
BC-1.13.002 applied to the online-services seam).

## Preconditions

1. The online-services adapter manifest is valid (BC-15.01.001 passed).
2. At least one capability is declared with `fidelity: none`.
3. The factory core (or a pipeline step) attempts to call the JSON-RPC method
   corresponding to that none-fidelity capability.

## Postconditions

1. **PASS — CapabilityUnsupported returned:** Calling any JSON-RPC method for a
   `fidelity: none` capability returns JSON-RPC error code `-32001`
   (E-EAP-002 `CapabilityUnsupported`). The response body includes the capability name
   and fidelity in the `data` field.
2. **PASS — core degrades without pipeline halt:** The factory core receives
   `CapabilityUnsupported` and degrades the affected convergence dimension (or marks
   the capability as not available) without halting the pipeline. This matches the
   behavior specified in BC-1.13.002 for the engine-adapter seam.
3. **FAIL — crash on none-fidelity call:** The adapter crashes (process exit, unhandled
   exception) when called for a `none`-fidelity capability. Error: `E-EAP-006`
   (`OperationFailed`) at the transport level. This is a conformance failure.
4. **FAIL — silent success on none-fidelity call:** The adapter returns a nominal success
   response for a `none`-fidelity capability (e.g., returns `{token: "fake"}` for an
   identity method when `identity: none`). Error: `E-OSVC-012`
   (`CapabilityUnsupportedSuppressed`). Treated as a conformance failure.
5. **FAIL — pipeline halt on CapabilityUnsupported:** The factory core propagates
   `CapabilityUnsupported` as a pipeline-halting error instead of gracefully degrading.
   This is a core implementation defect, not an adapter defect.

## Invariants

1. `CapabilityUnsupported` is the ONLY valid response to a call on a `none`-fidelity
   capability. No other response (success, other error, crash) is acceptable.
2. The core must treat `CapabilityUnsupported` from any online capability as a degrade
   signal, not an abort signal.
3. Silent truncation (logging neither the degradation nor the reason) is forbidden per
   the base protocol (adapter-protocols.md §1.5).

| EC-001 | `matchmaking.fidelity: none`; `online.matchmaking.createLobby` called | E-EAP-002 CapabilityUnsupported; pipeline continues |

| EC-005 | Core catches E-EAP-002 but logs nothing about the degradation | Forbidden: silent truncation violates base protocol; core must log degradation |
