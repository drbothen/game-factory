# BC-15.08.001: Conformance Suite Self-Report (Full vs. None Fidelity)

## Description

Every online-services adapter must self-report whether it ships its conformance suite by
declaring `capabilities.conformance_suite.fidelity` as either `full` or `none` in its
manifest. `full` means the adapter ships all five conformance test parts (manifest
validation, per-capability functional, graceful degradation, server-authority, and
offline-project path). `none` means the adapter does not ship a conformance suite. The
conformance suite acceptance gate (CAP-002 pattern) uses this self-report to determine
whether the adapter can be accepted for production use. An adapter declaring `full` that
fails any conformance suite test is rejected from production; an adapter declaring `none`
is accepted only for development/sandbox use, not production.

## Preconditions

1. The online-services adapter manifest is being evaluated for acceptance
   (pre-adapter-accept hook).
2. The adapter's manifest has passed basic schema validation (BC-15.01.001 passed).

## Postconditions

1. **PASS — conformance_suite: full, all tests pass:** The adapter declares
   `conformance_suite.fidelity: full` and all five conformance suite parts pass. The
   adapter is accepted for production use. Acceptance gate PASSES.
2. **FAIL — conformance_suite: full, test(s) fail:** The adapter declares `full` but
   one or more conformance tests fail. Error: `E-CONF-004` (`ConformanceAcceptanceGate`).
   The adapter is NOT accepted. Writes to the online-services configuration are blocked.
3. **PASS — conformance_suite: none, development use only:** The adapter declares `none`.
   It is accepted only for development/sandbox environments. A warning `E-OSVC-010`
   (`NoConformanceSuite`) is logged. The adapter may NOT be used in a production pipeline
   gate (convergence dimension D-SEC will flag missing conformance evidence).
4. **PASS — graceful degradation coverage:** For any capability with `fidelity: none`,
   the conformance suite verifies that calling it returns `CapabilityUnsupported`
   (not a crash). This is part of the `full` suite's part 3.
5. **PASS — server-authority coverage:** The suite submits a tampered score and a false
   entitlement claim; asserts both are rejected by the adapter's server-side validation.
   This is part of the `full` suite's part 4.

## Invariants

1. `conformance_suite.fidelity` must be exactly `full` or `none` — no other value.
2. An adapter declaring `full` that has not run the suite is treated as if it declared
   `none` until the suite run produces a passing report.
3. The conformance suite result is a per-adapter, per-version artifact — it is not
   version-inherited.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Adapter declares `full`; server-authority test fails (tampered score accepted) | E-CONF-004 acceptance gate failure; adapter not accepted |
| EC-002 | Adapter declares `none` | Accepted for dev/sandbox; warning logged; not accepted for production |
| EC-003 | Adapter declares `full`; graceful degradation test for a `none`-fidelity capability crashes instead of returning CapabilityUnsupported | E-CONF-004; adapter rejected |
| EC-004 | Adapter version bumped; previous conformance report was `full`/passing | Suite must be re-run for the new version; prior result does not carry over |
