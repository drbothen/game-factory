# BC-15.01.001: Online-Services Manifest Schema Validation and serverAuthoritative Enforcement

## Description

Every online-services adapter must return a structurally valid Capability Manifest on
`initialize` that satisfies all required fields from the base schema (§1.3) plus the
online-services delta fields (adapter-protocols.md §6.2). Critically, any manifest
declaring non-`none` fidelity for `leaderboards` or `entitlements` MUST set
`serverAuthoritative: true`; `false` on those capabilities is a malformed manifest
(E-EAP-012). Offline projects (offlineProject: true) skip this validation entirely and
produce zero BaaS configuration artifacts.

## Preconditions

1. The factory core sends an `initialize` request to the online-services adapter subprocess
   (JSON-RPC 2.0 stdio, LSP framing) or calls `capabilities()` on an HTTP adapter.
2. The adapter returns a manifest JSON object.
3. The project genre-profile is available to determine `online_features` and `offlineProject`.

## Postconditions

1. **PASS — valid manifest:** The manifest contains all required fields: `seam` equals
   `"online-services-adapter"`, `targetId`, `targetVersion`, `adapterVersion`,
   `protocolVersion`, `selfHostable` (bool), `testModeSupport` (bool), `offlineProject`
   (bool), and `capabilities` object with at least `identity`, `cloud_save`, `leaderboards`,
   `matchmaking`, `entitlements`, `remote_config`, and `conformance_suite` declared. Each
   declared capability carries a valid `fidelity` enum value
   (`full | partial | none | human-gated`). The core proceeds with capability negotiation.
2. **FAIL — missing required field:** Any mandatory top-level field is absent or null.
   Error: `E-EAP-012` (`MalformedManifest`). The core refuses to proceed; the adapter is
   not accepted. Message: `online-services manifest rejected: required field '<field>' absent`.
3. **FAIL — serverAuthoritative: false on leaderboards:** `capabilities.leaderboards.fidelity`
   is non-`none` and `capabilities.leaderboards.serverAuthoritative` is `false` or absent.
   Error: `E-EAP-012` (`MalformedManifest`). Message: `online-services manifest rejected:
   leaderboards.serverAuthoritative must be true for non-none fidelity — client-authority
   leaderboard submission violates BC-15.01.001 and D-SEC BC-7.11.*`.
4. **FAIL — serverAuthoritative: false on entitlements:** `capabilities.entitlements.fidelity`
   is non-`none` and `capabilities.entitlements.serverAuthoritative` is `false` or absent.
   Error: `E-EAP-012` (`MalformedManifest`). Message: `online-services manifest rejected:
   entitlements.serverAuthoritative must be true for non-none fidelity`.
5. **OFFLINE SKIP:** `offlineProject: true` in manifest OR `online_features: false` in
   project genre-profile. The core skips all online-services capability validation, produces
   zero BaaS configuration artifacts, and does NOT fail the pipeline. Capability fidelity for
   all seven capabilities must be `none` when `offlineProject: true`.

## Invariants

1. `serverAuthoritative: true` is non-negotiable for any non-`none` leaderboard or
   entitlement fidelity. The adapter cannot override this at runtime.
2. `offlineProject: true` implies all capability fidelities are `none` — a manifest with
   `offlineProject: true` and any capability with non-`none` fidelity is malformed.
3. The `seam` field must be exactly `"online-services-adapter"` — no other value is accepted.
4. `targetVersion` must be a pinned version string, not a range or `"latest"`.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Manifest with `leaderboards.serverAuthoritative: false` | FAIL: E-EAP-012; adapter not accepted |
| EC-002 | Manifest missing `selfHostable` field | FAIL: E-EAP-012; adapter not accepted |
| EC-003 | `offlineProject: true` with `leaderboards.fidelity: full` | FAIL: E-EAP-012; offline project may not declare non-none fidelity |
| EC-004 | `targetVersion: "latest"` | FAIL: E-EAP-012; floating version string rejected |
| EC-005 | HTTP adapter returning capabilities via `capabilities()` call | PASS: same schema validation applies regardless of transport |
| EC-006 | Manifest declares only `identity` and all others `none` | PASS: partial feature set is valid as long as schema is correct |
