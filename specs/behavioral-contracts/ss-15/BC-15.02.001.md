# BC-15.02.001: Identity — Player Account Create and Authenticate with Session Token and Expiry

## Description

The online-services adapter must support player account creation and session
authentication via `online.identity.create` and `online.identity.authenticate`. On
success, both methods return a session token with a declared expiry (`expiresAt`). The
session token is used for all subsequent authenticated requests. Expired tokens are
rejected with `E-OSVC-002` (SessionExpired). Token TTL is declared in the manifest's
`identity.sessionTTLSeconds` field; zero means adapter default (must be documented).

## Preconditions

1. The online-services adapter manifest has been validated (BC-15.01.001 passed).
2. `capabilities.identity.fidelity` is `full` or `partial` (not `none`).
3. The BaaS backend (e.g., Nakama) is reachable (not in offline-project mode).
4. The `authProvider` value is in the adapter's declared `authProviders` list.

## Postconditions

1. **PASS — create:** `online.identity.create` with valid `{playerId, authProvider, credentials}`
   returns `{token: "<jwt-or-opaque>", playerId: "<string>", created: true}` when the account
   does not yet exist, or `{token: ..., playerId: ..., created: false}` when it already exists
   (idempotent upsert). `token` is a non-empty string.
2. **PASS — authenticate:** `online.identity.authenticate` with valid credentials returns
   `{token: "<string>", expiresAt: "<ISO-8601>"}`. `expiresAt` must be in the future at
   time of issuance; `expiresAt` must be parseable as ISO-8601.
3. **FAIL — backend unreachable:** Backend connection fails. Error: `E-OSVC-001`
   (`BackendUnreachable`). The core logs degradation; does not halt pipeline unless
   `identity` is on the critical path for the current wave.
4. **FAIL — invalid credentials:** Credentials rejected by the backend. Error: `E-OSVC-002`
   with `error.data.reason = "INVALID_CREDENTIALS"` (REQUIRED — callers MUST be able to
   distinguish this from SessionExpired). Message: `online.identity.authenticate: credentials
   rejected for playerId '<id>' via provider '<provider>'`.
5. **FAIL — expired session token used on subsequent call:** Any online method called with
   an expired token returns `E-OSVC-002` with `error.data.reason = "SESSION_EXPIRED"`
   (REQUIRED — callers MUST be able to distinguish this from InvalidCredentials). The caller
   must re-authenticate.
6. **FAIL — unsupported auth provider:** `authProvider` not in `identity.authProviders`.
   Error: `E-OSVC-013` (`UnsupportedAuthProvider`).

## Invariants

1. Every session token has a declared `expiresAt`. A token without expiry is an error.
2. Token refresh does not automatically re-authenticate expired sessions; explicit
   re-authentication is required.
3. `playerId` is treated as the stable identity key; the same `playerId` with the same
   provider always resolves to the same account (no duplicate accounts per provider+id).

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | `online.identity.create` called twice with same playerId+provider | PASS: `created: false` on second call; token returned |
| EC-002 | `expiresAt` in past when token arrives (clock skew) | Token treated as already expired; E-OSVC-002 on first use |
| EC-003 | Backend unreachable during `create` | E-OSVC-001; pipeline degrades, does not halt |
| EC-004 | `authProvider: "unknown-provider"` | E-OSVC-013 UnsupportedAuthProvider |
| EC-005 | `identity.fidelity: none` | Returns CapabilityUnsupported (E-EAP-002) for all identity methods |
