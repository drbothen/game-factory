# BC-15.06.001: Entitlements — Server-Authoritative Verify, Granted:False for Unowned, Human-Gated Platform-Store-Review Path

## Description

The online-services adapter must verify player entitlements (DLC ownership, season pass,
premium tier) server-side via `online.entitlement.verify`. The server queries its
authoritative entitlement store (populated from platform SDK receipt validation) — never
from client assertion. If the entitlement is not owned, the response is
`{granted: false, expiresAt: null}`. A client claiming ownership without server
verification MUST be rejected. For some store platforms (e.g., Apple IAP), entitlement
verification requires a platform store review step: these are declared as
`entitlements: human-gated` in the manifest, and the adapter surfaces a
`<platform>-entitlement-store-review` checklist item via DI-006.

**The server-authority principle for entitlements is governed by D-SEC BC-7.11.008.
This BC specifies the operational contract for the online-services adapter's entitlement
path. Violations surface through the D-SEC dimension — this BC does NOT duplicate the
server-authority spine.**

## Preconditions

1. The online-services adapter manifest is valid (BC-15.01.001 passed).
2. `capabilities.entitlements.serverAuthoritative` is `true` (enforced by BC-15.01.001).
3. `capabilities.entitlements.fidelity` is `full`, `partial`, or `human-gated`.
4. A valid session token has been obtained (BC-15.02.001 passed).
5. The entitlement store backend is configured and the entitlement ID is registered.

## Postconditions

1. **PASS — entitlement granted:** `online.entitlement.verify` with `{playerId, entitlementId}`
   where the player holds the entitlement returns `{granted: true, expiresAt: "<ISO-8601>|null"}`.
   `expiresAt` is null for permanent entitlements, non-null for time-limited access.
2. **PASS — entitlement not granted:** Player does not own the entitlement. Returns
   `{granted: false, expiresAt: null}`. This is NOT an error — it is a legitimate query
   result. No exception is raised.
3. **FAIL — client-asserted entitlement bypass:** Client sends a request that implies
   entitlement ownership without going through `online.entitlement.verify` (e.g., a modified
   client that skips the verify call). This is a D-SEC violation governed by BC-7.11.008.
   Error path: `E-CONV-006` (`D-SEC dimension non-green`). The online-services adapter is
   not responsible for detecting this attack — the server-side game logic gate is (BC-7.11.008).
4. **FAIL — entitlement not found in store registry:** `entitlementId` is not a registered
   entitlement in the backend. Error: `E-OSVC-004` variant `EntitlementNotFound`.
   Message: `entitlement.verify: entitlementId '<id>' not registered in backend store`.
5. **HUMAN-GATED — platform store review:** When `capabilities.entitlements.fidelity` is
   `human-gated`, calling `online.entitlement.verify` surfaces a checklist item
   `<platform>-entitlement-store-review` via the factory's human-gated task mechanism (DI-006).
   The adapter does NOT autonomously complete this terminal step. The D-SEC and D-CERT
   convergence dimensions remain blocked until the human acknowledges the task.
6. **FAIL — backend unreachable:** Error: `E-OSVC-001` (`BackendUnreachable`). Fail-closed:
   treat all entitlements as `granted: false` when store is unreachable (no fail-open).

## Invariants

1. `granted: false` is the correct, non-error response for an unowned entitlement.
2. Fail-closed on backend unreachability: when the entitlement store cannot be reached,
   all entitlements default to `granted: false`. Fail-open is a BLOCKED configuration.
3. Platform store receipt validation is the only permitted source for populating the
   entitlement store — not client assertions, not factory-generated receipts.
4. The `human-gated` entitlement path never auto-completes the terminal step (DI-006).

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Player owns entitlement; standard query | `{granted: true, expiresAt: null}` |
| EC-002 | Player does NOT own entitlement | `{granted: false, expiresAt: null}` — not an error |
| EC-003 | Entitlement store unreachable; `deny_access` fallback | `{granted: false, expiresAt: null}` with E-OSVC-001 logged |
| EC-004 | `entitlementId` not in registry | E-OSVC-004 EntitlementNotFound |
| EC-005 | `entitlements: human-gated`; verify called | Checklist item surfaced; D-SEC blocked; no autonomous completion |
| EC-006 | Time-limited entitlement past expiry | `{granted: false, expiresAt: "<past-date>"}` — expired, not granted |
| EC-007 | `entitlements.fidelity: none` | E-EAP-002 CapabilityUnsupported |
