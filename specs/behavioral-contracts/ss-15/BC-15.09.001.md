# BC-15.09.001: Online-Services Seam Isolation — Zero Core Changes on Adapter Add/Remove

## Description

Adding, removing, or replacing an online-services adapter must produce zero changes to
factory core layers 1-2 source files. All online-services backend knowledge is
quarantined in Layer-4 adapter implementations. The core drives the adapter through the
base protocol (§1.2 lifecycle, §6.4 JSON-RPC methods) and interprets the manifest
(BC-15.01.001) — it never imports a BaaS SDK or references a specific backend (Nakama,
EOS, PlayFab) by name. This is the direct application of ADR-0004 (adapter-family
anti-lock-in) to the online-services seam.

## Preconditions

1. A factory core build exists at a known commit hash.
2. An online-services adapter is added, removed, or swapped (different `targetId`).
3. No other changes are made in the same operation.

## Postconditions

1. **PASS — zero core changes:** After adding, removing, or swapping the online-services
   adapter, the diff of factory core layer 1-2 source files is empty. No core file imports
   a BaaS SDK (e.g., `nakama-js`, `epic-online-services`, `playfab-sdk`). No core file
   references a BaaS backend name as a string constant.
2. **FAIL — core changed:** Any factory core layer 1-2 source file is modified as a result
   of the adapter operation. Error: `E-OSVC-011` (`OnlineServicesCoreCouplingDetected`).
   Message: `online-services adapter add/remove caused core file '<file>' to change —
   violates seam isolation (BC-15.09.001, ADR-0004)`.
3. **FAIL — backend name in core:** Static analysis detects a BaaS backend name (nakama,
   eos, playfab, or any configured backend `targetId`) in core layer 1-2 source as a
   string literal or import symbol. Error: `E-OSVC-011`.

## Invariants

1. All BaaS backend names are quarantined in Layer-4 adapter configuration and manifest
   files. The core knows only the abstract `seam: "online-services-adapter"` interface.
2. The core accesses online-services capabilities exclusively through the JSON-RPC
   method set (§6.4) and manifest capability declarations — never through backend-native APIs.
3. This invariant is DI-001's application to online services: "Factory Core Never Names
   a Specific Engine" applies equally to BaaS backends.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Swap Nakama adapter for EOS adapter | Zero core changes; only Layer-4 adapter files change |
| EC-002 | Core file includes `import nakama from 'nakama-js'` | FAIL: E-OSVC-011 core coupling detected |
| EC-003 | Core config file has `defaultBackend: "nakama"` as a configuration value (not a source import) | Permitted if in Layer-3 config only — flagged for review if in Layer 1-2 source |
| EC-004 | Remove online-services adapter entirely (offline project) | Zero core changes; capability path degrades gracefully per BC-15.01.002 |
