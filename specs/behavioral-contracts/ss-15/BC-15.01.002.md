# BC-15.01.002: Off-by-Default Posture — Offline/Single-Player Zero-Artifact Guarantee

## Description

When a project declares `online_features: false` in its genre-profile OR the
online-services adapter manifest declares `offlineProject: true`, the factory produces
zero BaaS configuration artifacts, triggers no conformance suite run, and does NOT fail
the pipeline. This is a project-level toggle, not a genre-gated lane — any project type
may disable online services. A single-player game with `online_features: false` must
produce an identical pipeline result to a project that never had online services
configured at all.

## Preconditions

1. The project genre-profile is loaded and contains an `online_features` field OR the
   online-services adapter manifest declares `offlineProject: true`.
2. At least one of the following is true: `online_features: false` in genre-profile, or
   `offlineProject: true` in the adapter manifest.

## Postconditions

1. **PASS — zero artifacts:** The factory produces zero BaaS configuration files. The
   output artifact tree contains no files attributable to the online-services capability
   (e.g., no `baas-config.json`, no `online-services-manifest.json`, no identity
   configuration, no leaderboard schema, no matchmaking configuration).
2. **PASS — no conformance run:** The online-services conformance suite is NOT invoked.
   No conformance report for online-services appears in the output.
3. **PASS — no pipeline failure:** The pipeline completes without error. Absence of
   online-services output is not treated as a missing artifact.
4. **PASS — CapabilityUnsupported on any online capability call:** If any downstream
   pipeline step attempts to call an online-services method (e.g., `online.identity.create`),
   the adapter returns `CapabilityUnsupported` (E-EAP-002). The core degrades gracefully
   without pipeline halt.
5. **FAIL — artifact leak:** Any BaaS configuration artifact appears in the output tree
   when `online_features: false` or `offlineProject: true`. Error: `E-OSVC-009`
   (`OnlineArtifactLeakInOfflineProject`). This is a hard pipeline failure.

## Invariants

1. `online_features: false` is a project-level toggle, not genre-gated. It applies
   regardless of whether `esports_enabled`, `matchmaking_enabled`, or any other lane
   flag is set.
2. An offline project's adapter manifest must declare all capability fidelities as `none`.
   This is validated by BC-15.01.001 Postcondition 5.
3. The zero-artifact guarantee is machine-verifiable: the conformance suite can enumerate
   expected online-services artifact paths and assert none are present.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | `online_features: false` in genre-profile; adapter manifest not present at all | PASS: no adapter invoked; zero BaaS artifacts |
| EC-002 | `online_features: false` but `esports_enabled: true` (esports lane relies on matchmaking) | PASS: online-services still zero-artifact; esports lane degrades to D-SEC not-applicable per lane isolation |
| EC-003 | Adapter manifest present with `offlineProject: true`; downstream step calls `online.save.write` | CapabilityUnsupported (E-EAP-002) returned; core degrades, no pipeline failure |
| EC-004 | Re-running pipeline on same offline project (idempotency) | Same zero-artifact result on every run |
| EC-005 | `online_features` field absent from genre-profile (not set to false, just absent) | Default: treat as `online_features: true` — online services are enabled |

## Canonical Test Vectors
