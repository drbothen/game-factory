# BC-12.12.002: Entity Registry — Registration, Lookup, and Stable-ID Guarantee

## Description

The entity-registry subsystem of the Canon-KB accepts new canon entities (characters,
factions, locations, items, events, concepts) via a registration operation that assigns
a stable, content-addressable `entity_id`. Once assigned, an `entity_id` is never
reused or reassigned, even if the entity is later deprecated or removed. The registry
supports lookup by `entity_id` and by `canonical_name` with deterministic results.

## Preconditions

1. The `canon-kb` for the target `game_id` exists and is `status: initialized` or later.
2. The registration request contains all mandatory fields: `entity_type`,
   `canonical_name`, `canon_tier`, `provenance` (source artifact reference).
3. The requesting agent has write authorization for the Canon-KB
   (`worldbuilder` or `loremaster` roles have write authorization; generative agents
   have read-only access).

## Postconditions

1. A new entry is created in `entity-registry/` with:
   - `entity_id`: a stable, deterministic, globally unique ID for this game (format:
     `<game_id>/<entity_type>/<slug>` derived from canonical_name; slug is
     content-addressable and stable even if the name is later updated)
   - `canonical_name`: exactly as provided at registration time
   - `aliases: []` (empty initially; aliases may be added later)
   - `entity_type`, `canon_tier`, `status: active`, `provenance` as provided
   - `introduced_event_id: null` (set when the entity is linked to a timeline event)
   - `departed_event_id: null` (set when applicable)
2. The `entity_id` is returned to the caller.
3. A `canonical_name → entity_id` mapping is added to the naming-registry lookup index
   for collision detection (does not modify the naming-registry's phonotactic rules).

## Invariants

1. Two distinct entities may not share a `canonical_name` within the same `game_id`
   scope unless one has `status: retired` — this is the naming-collision invariant.
   A collision attempt is rejected with `CANONICAL_NAME_COLLISION`.
2. `entity_id` values are immutable after assignment. Renaming an entity updates
   `canonical_name` and `aliases` but NEVER changes the `entity_id`.
3. The `entity-registry` is append-only for `status: active` entities. Removing an
   entity transitions it to `status: retired`; the record is retained for cross-reference
   integrity.
4. `entity_type` must be one of the declared values: `character | faction | location |
   item | event | concept`. Unknown types are rejected.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Registration with a `canonical_name` that already exists in the registry (active entity) | Rejected: E-KB-005 (`CANONICAL_NAME_COLLISION`); returns the existing entity's `entity_id` in `error.data.reason` so the caller can decide whether to use the existing entry or escalate to the loremaster |
| EC-002 | Registration with a name that exists but the existing entity is `status: retired` | Allowed with a warning: E-KB-008 (`RETIRED_NAME_REUSE`); the new entity gets a new `entity_id`; the retired entity record is preserved |
| EC-003 | Registration with a `canonical_name` matching a `forbidden_names` entry in the naming-registry | Rejected: E-KB-010 (`FORBIDDEN_NAME`); the caller must choose an alternate name |
| EC-004 | Caller attempts to update `entity_id` after registration | Rejected: E-KB-009 (`ENTITY_ID_IMMUTABLE`) |
| EC-005 | Caller registers a name with a spelling that differs only in capitalization from an existing entity (e.g. "Azara" vs "azara") | Rejected: E-KB-005 (`CANONICAL_NAME_COLLISION`) (case-insensitive comparison for collision detection) |
| EC-006 | Bulk registration of many entities in one request | All entities processed atomically; if any fails (e.g. a collision), the entire batch is rejected and no partial writes occur |

## Canonical Test Vectors

| Input | Expected Output | Category |
|-------|----------------|----------|
| `{entity_type: character, canonical_name: "Kael", canon_tier: hard, provenance: "world-bible/v1.0"}` | Entity registered; `entity_id: "pilot-roguelike/character/kael"` returned | happy-path |
| Registration of `canonical_name: "Kael"` when "Kael" already exists as active character | E-KB-005 (`CANONICAL_NAME_COLLISION`); existing entity_id in error.data | error (EC-001) |
| Registration with name "Azara" when "azara" exists (case mismatch) | E-KB-005 (`CANONICAL_NAME_COLLISION`) (case-insensitive) | error (EC-005) |
| Attempt to set `entity_id: "custom-id"` after registration | E-KB-009 (`ENTITY_ID_IMMUTABLE`) | error (EC-004) |
| Batch registration of 3 entities where entity 2 has a name collision | Entire batch rejected; no entities written | error (EC-006 / atomicity) |

## Verification Properties

| VP | Property | Proof Method |
|----|----------|-------------|
| VP-1 | For all registered entities, `entity_id` is unique within the `game_id` scope — no two entities may ever share an `entity_id` | Property-based test: register arbitrary sequences of entities; assert all `entity_id` values are unique |
| VP-2 | For all active entities, `canonical_name` values are unique (case-insensitive) within `game_id` | Property-based test: attempt name collisions in various casing combinations; assert all rejected |
| VP-3 | Retiring an entity does not remove its record — the `entity_id` reference remains resolvable | Test: register entity, retire it, look up by `entity_id`; assert record returned with `status: retired` |
