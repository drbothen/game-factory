# BC-12.12.005: Naming-Registry — Collision Detection and Phonotactic Rule Enforcement

## Description

The naming-registry subsystem maintains canonical spellings, phonotactic rules per
culture/faction, reserved/forbidden names, and a conlang lexicon. Before any generated
name (character, location, faction, item) is accepted into the canon, the factory checks
it against the naming-registry for collisions, forbidden patterns, and phonotactic
conformance. Detected issues are either hard-blocked or flagged for loremaster review,
depending on severity.

## Preconditions

1. The `canon-kb` for the target `game_id` is initialized.
2. The naming-registry for the game has at minimum an initialized (possibly empty)
   `canonical_spellings: {}` store, `reserved_names: []`, and `forbidden_names: []`.
3. A name-check request includes: `proposed_name`, `entity_type`, `culture_context`
   (optional; if provided, phonotactic rules for that culture apply).

## Postconditions

1. **If the name passes all checks**, the factory returns `{status: clear, proposed_name}`.
   The name is not automatically registered — clearance is a prerequisite for registration,
   not a registration act.
2. **If a collision is detected** (exact match or case-insensitive near-match with an
   existing canonical name), the factory returns:
   `{status: collision, conflicting_entity_id, conflicting_name}`.
3. **If the name matches a forbidden pattern**, the factory returns:
   `{status: forbidden, reason}`.
4. **If the name violates phonotactic rules** for the declared `culture_context`, the
   factory returns: `{status: phonotactic_violation, violated_rule, suggestion}`.
5. The name-check result is logged (for audit trail) but does not modify the naming-registry.
   Only the loremaster or worldbuilder can add names to `canonical_spellings` or
   `forbidden_names`.

## Invariants

1. Name collision detection is case-insensitive and diacritic-normalized: "Kael",
   "kael", and "Käel" are treated as collisions unless the canonical spelling explicitly
   distinguishes them via a diacritic policy in the game's naming-registry config.
2. Phonotactic rules are culture-scoped: a name that violates the "Human Empire" culture's
   phonotactics may be perfectly valid for the "Myrid" culture. Rules must be consulted
   against the correct culture scope.
3. The `forbidden_names` list is authoritative and not overridable by any agent — only
   the loremaster may modify it. A forbidden name may never become a `canonical_spelling`.
4. The naming-registry must be consulted before ANY new name enters the canon (entity
   registration, generated bark names, item names, location names). Skipping the check
   is a `NAMING_REGISTRY_BYPASSED` defect.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Name check with no `culture_context` and phonotactic rules exist for some cultures | Phonotactic check is skipped (no culture specified); collision and forbidden checks still run; result notes `phonotactic_check_skipped: true` |
| EC-002 | A generated bark references a character name not in the entity-registry (name was never registered) | Flagged as `UNREGISTERED_NAME_IN_CONTENT`; not a phonotactic or collision issue — this is entity-reference integrity (see BC-12.12.007) |
| EC-003 | Proposed name appears in `reserved_names` (e.g. the name is reserved for a future entity not yet registered) | Returns `{status: reserved, reserved_for: <description>}`; the caller may proceed only with loremaster authorization |
| EC-004 | Naming-registry has no rules configured (game's world-bible not yet seeded) | All checks pass vacuously; result includes `{registry_unconfigured: true}`; advisories suggest seeding the registry before bulk content generation |
| EC-005 | Proposed name is a direct concatenation of two forbidden names | Flagged as `FORBIDDEN_NAME` if the game's naming-registry config has `compound_forbidden: true`; otherwise, the individual components are checked but the compound is not blocked |

## Canonical Test Vectors

| Input | Expected Output | Category |
|-------|----------------|----------|
| `{proposed_name: "Varek", entity_type: character, culture_context: "human-empire"}`, phonotactic rules allow V-start | `{status: clear, proposed_name: "Varek"}` | happy-path |
| `{proposed_name: "Kael"}`, "kael" already exists as active character | `{status: collision, conflicting_entity_id: "pilot-roguelike/character/kael", conflicting_name: "Kael"}` | error |
| `{proposed_name: "xz'kar"}`, culture "human-empire" forbids consonant clusters >3 | `{status: phonotactic_violation, violated_rule: "max_consonant_cluster=3", suggestion: "xzkar"}` | error |
| `{proposed_name: "Kael"}`, naming-registry is unconfigured (empty) | `{status: clear, registry_unconfigured: true}` (vacuous pass with advisory) | edge-case (EC-004) |

## Verification Properties

| VP | Property | Proof Method |
|----|----------|-------------|
| VP-1 | For all name-check calls, case-insensitive collision detection catches name matches regardless of capitalization | Property-based test: register name "Alpha"; check "alpha", "ALPHA", "aLpHa" — all return `status: collision` |
| VP-2 | No name in the `forbidden_names` list ever appears as a `canonical_spelling` in the naming-registry | CI check: assert intersection of `forbidden_names` and `canonical_spellings.keys()` is always empty |
