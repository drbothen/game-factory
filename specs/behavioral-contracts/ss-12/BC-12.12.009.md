# BC-12.12.009: RAG-Grounding Contract — All Generative Agents Ground Against Canon-KB

## Description

Before any generative agent (worldbuilder, systemic-writer, bark-writer, codex-writer,
quest-designer, copywriter) produces a narrative artifact, it MUST retrieve the relevant
Canon-KB subgraph for all entities, facts, and timeline context pertinent to the
generation request. The retrieval is graph-shaped (entity-neighborhood subgraph), not
purely vector-similarity search. The retrieved canon context is injected as constraints
into the generation call. This BC applies to all CAP-005 generative agents producing
narrative/lore content — and is a cross-capability grounding obligation affecting
CAP-004 (asset descriptions) and CAP-005 (multi-discipline production).

## Preconditions

1. The `canon-kb` for the target `game_id` is initialized with at minimum one entity
   registered (a completely empty KB vacuously grounds — acceptable for the pilot
   bootstrap pass, but subsequent generations must ground against whatever exists).
2. A generation request has been issued to a generative agent: `{generation_type,
   entity_context_ids[], topic, game_id}`.
3. The generative agent is on the list of agents required to ground (all narrative-domain
   agents; asset-description agents; any agent producing text that names entities).

## Postconditions

1. Before generation, the agent queries the Canon-KB for:
   - Entity records for each ID in `entity_context_ids`
   - All relationships involving those entities (1-hop neighborhood from the
     relationship-graph)
   - Relevant timeline events (events within which the topic is temporally scoped)
   - Hard and soft canon-facts asserting properties of those entities
   - Naming-registry entries for the entities (canonical spellings, aliases)
2. The retrieved subgraph (structured JSON/schema — NOT prose summary) is injected
   as a `canon_context` field in the generation prompt.
3. The generated artifact is tagged with `grounded_against: {kb_version, retrieved_entity_ids[],
   retrieved_fact_ids[], retrieval_timestamp}` for audit and retcon propagation.
4. After generation, the artifact is automatically submitted to the continuity check
   battery (BC-12.12.007) before being accepted.
5. If the Canon-KB is completely empty (`entity_count = 0`) at generation time, the
   agent proceeds with `canon_context: null` and the output is tagged
   `ungrounded_bootstrap: true`. This state is acceptable only during initial world-bible
   seeding — the loremaster must ratify any ungrounded artifact before it can be used
   as a source for canon-fact registration.

## Invariants

1. No generative agent on the required-grounding list may produce a narrative artifact
   without first retrieving canon context (even if the context turns out to be empty).
   A generation call without a `grounded_against` tag is a `GROUNDING_BYPASSED` defect.
2. The `canon_context` injected into the generation prompt must be structured data
   (entity records, fact assertions, relationship edges) — NOT an LLM-generated prose
   summary of the KB. This prevents grounding quality degradation through summarization.
3. The grounding retrieval must be reproducible: given the same `{entity_context_ids[],
   kb_version}`, the same subgraph is returned (deterministic retrieval).
4. An artifact with `ungrounded_bootstrap: true` may not be used as `source_artifact_ref`
   in canon-fact registration until the loremaster has reviewed and ratified it.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Entity ID in `entity_context_ids` does not exist in the registry | That ID returns an empty result (not an error); retrieval continues for other IDs; the missing entity is noted in the `grounded_against` metadata as `unresolved_entity_ids: [...]` |
| EC-002 | Canon-KB is partially initialized (some subsystems missing) | Retrieval operates over available subsystems; missing subsystems return empty results; artifact is tagged `partial_grounding: true`; defect emitted to `loremaster` |
| EC-003 | Generative agent is a CAP-004 asset-generation agent generating a character model description | The agent must retrieve the character's entity record and canonical facts (appearance, status) from the KB before generating — asset descriptions are in scope for grounding |
| EC-004 | Generation request has no `entity_context_ids` (open-ended world-expansion request) | Agent must at minimum retrieve the top-level world-bible entities (all `concept` and `faction` entities) as context; a completely context-free generation is not permitted for non-bootstrap cases |
| EC-005 | Retrieval times out (KB query exceeds declared timeout) | Generation is blocked; a `GROUNDING_TIMEOUT` error is returned; the generation request is retried after the KB query performance issue is investigated |

## Canonical Test Vectors

| Input | Expected Output | Category |
|-------|----------------|----------|
| Bark generation request: `{entity_context_ids: ["kael", "iron-guild"], game_id: "pilot-roguelike"}` | KB retrieval returns kael entity + iron-guild entity + their shared relationships + timeline events; `canon_context` injected; artifact generated and submitted to continuity battery | happy-path |
| Same request with empty Canon-KB (bootstrap) | Generation proceeds with `canon_context: null`; artifact tagged `ungrounded_bootstrap: true` | edge-case (EC-001 bootstrap variant) |
| CAP-004 asset description agent generates character model description for "Kael" | KB retrieval for "kael" entity performed first; description grounded against canonical appearance facts | edge-case (EC-003) |
| Grounding retrieval timeout | Error: `GROUNDING_TIMEOUT`; generation blocked | error (EC-005) |

## Verification Properties

| VP | Property | Proof Method |
|----|----------|-------------|
| VP-1 | For all narrative artifacts in the artifact store (excluding `ungrounded_bootstrap: true`), a `grounded_against` field is present and non-empty | Schema validation + property-based test over all artifact types subject to grounding |
| VP-2 | No narrative artifact transitions to `status: continuity-cleared` without first having a `grounded_against` tag (grounding is a prerequisite for the continuity check gate) | State-machine test: attempt to run continuity check on artifact without `grounded_against`; assert rejected |
| VP-3 | Deterministic retrieval: for the same `{entity_context_ids, kb_version}`, the same canonical subgraph is returned | Property-based test: call retrieval twice with same inputs; assert identical results |
