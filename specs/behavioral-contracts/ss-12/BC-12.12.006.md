# BC-12.12.006: Canon-Facts — Assertion Registration with Tier and Provenance

## Description

The canon-facts subsystem accepts atomic world-truth assertions about entities and their
properties/states, each with declared provenance, canon-tier, and temporal validity. A
hard-canon fact that conflicts with an existing hard-canon fact on the same subject and
predicate within the same validity window is rejected as a contradiction (unless the
new fact carries a retcon declaration). Soft, contested, and ambiguous-by-design facts
are accepted alongside conflicting assertions with appropriate flagging.

## Preconditions

1. The `canon-kb` for the target `game_id` is initialized.
2. The fact registration request includes: `subject_entity_id`, `predicate`, `object`,
   `source_artifact_ref`, `canon_tier`, and optionally `valid_from_event_id`,
   `valid_to_event_id`, `ambiguity_flag`.
3. `subject_entity_id` must exist in the entity-registry.
4. If `valid_from_event_id` or `valid_to_event_id` are provided, they must exist in
   the timeline.

## Postconditions

1. If no contradiction exists (or tier allows coexistence), a `canon-fact` is created:
   - `fact_id`: stable unique ID
   - All provided fields plus `registered_at` timestamp
   - `ambiguity_flag` defaults to `false` if not provided
2. If a contradiction is detected between two `hard` tier facts on the same
   subject/predicate within overlapping temporal windows:
   - **Without `retcon: true`**: rejected with `HARD_CANON_CONTRADICTION`; error
     payload identifies the conflicting fact's `fact_id`
   - **With `retcon: true`**: the new fact is accepted; the conflicting fact is
     superseded and its `status` is updated to `superseded`; a
     `retcon-record` is created linking old fact → new fact
3. Contradictions between `soft` or `contested` facts are accepted with a
   `SOFT_CONTRADICTION_WARNING` annotation (not a hard rejection).
4. The new fact is immediately queryable.

## Invariants

1. The `source_artifact_ref` field is mandatory and must be non-empty — every canon
   assertion must trace to an artifact that introduced it (provenance requirement, DI-003
   analog for the narrative domain).
2. Two `hard-canon` facts with the same `subject_entity_id`, `predicate`, and overlapping
   temporal validity windows are a contradiction. The factory MUST detect and reject or
   explicitly retcon such conflicts — silent coexistence of conflicting hard-canon facts
   is a defect.
3. Facts with `ambiguity_flag: true` are intentional; they are exempt from contradiction
   checks. This models intentional unreliable-narrator or contested-canon design.
4. Retcon operations must be atomic: the new fact is accepted AND the superseded fact is
   marked in the same transaction. A partial retcon (new fact written, old fact not
   updated) is a defect.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Two hard-canon facts assert contradictory states (e.g. "Kael is alive" and "Kael is dead") in the same temporal window | Second fact rejected: `HARD_CANON_CONTRADICTION {conflicting_fact_id: ...}`; loremaster must either retcon or mark one as contested |
| EC-002 | New hard-canon fact registered with `retcon: true` over an existing hard-canon fact | Old fact marked `status: superseded`; new fact created; `retcon-record` written; a `where-used` impact list is returned identifying artifacts that referenced the superseded fact |
| EC-003 | Fact registered with `ambiguity_flag: true` that appears to contradict an existing hard-canon fact | Accepted without rejection; `ambiguity_flag` means the ambiguity is intentional and excludes this fact from contradiction checks |
| EC-004 | `source_artifact_ref` is empty or null | Rejected: `MISSING_PROVENANCE` |
| EC-005 | Fact asserted about a `status: retired` entity | Accepted with `SUBJECT_ENTITY_RETIRED` warning; historical facts about retired entities are legitimate |
| EC-006 | Two `soft` tier facts contradict each other | Both accepted; `SOFT_CONTRADICTION_WARNING` annotation on the second; loremaster notified for potential resolution |

## Verification Properties

| VP | Property | Proof Method |
|----|----------|-------------|
| VP-1 | For all facts in the canon-facts store with `canon_tier: hard`, no two facts share the same `subject_entity_id` and `predicate` within overlapping temporal windows unless one has `status: superseded` or `ambiguity_flag: true` | CI check: query all hard-canon facts; group by (subject, predicate); assert max one active non-ambiguous fact per temporal window |
| VP-2 | Every retcon operation is atomic: the superseded fact's `status` is `superseded` at the same version as the new fact's creation | Integration test: simulate retcon; assert atomicity via version comparison |
