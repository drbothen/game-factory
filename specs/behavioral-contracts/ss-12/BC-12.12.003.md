# BC-12.12.003: Relationship-Graph — Typed Edge Registration and Dangling-Reference Prevention

## Description

The relationship-graph subsystem of the Canon-KB stores typed, directional relationships
between registered entities (e.g. `ally_of`, `member_of`, `located_in`, `killed_by`,
`occurred_before`). Before any edge is registered, both endpoint entity IDs must exist
in the entity-registry. The factory prevents dangling entity references at write time,
not just at validation time.

## Preconditions

1. The `canon-kb` for the target `game_id` is initialized.
2. An edge registration request includes: `subject_entity_id`, `predicate`, `object_entity_id`,
   `canon_tier`, `provenance`. Both entity IDs must reference entities in the entity-registry.
3. The `predicate` must be drawn from the declared relationship-type vocabulary for the
   game's world-bible or from the universal base vocabulary (see Invariants).

## Postconditions

1. If both entity IDs exist as `status: active` in the entity-registry, a new edge is
   created in `relationship-graph/` with:
   - `edge_id`: stable unique ID
   - `subject_entity_id`, `predicate`, `object_entity_id` as provided
   - `canon_tier`, `provenance`
   - `valid_from_event_id: null` (may be set to a timeline event ID to indicate when
     the relationship became true)
   - `valid_to_event_id: null` (may be set to indicate when the relationship ended)
2. The edge is immediately queryable via `subject_entity_id` and `object_entity_id` lookup.
3. The edge write is rejected if either entity ID does not exist (dangling reference prevention).

## Invariants

1. **No-dangling-reference invariant** (machine-checkable, CI gate): both `subject_entity_id`
   and `object_entity_id` MUST resolve to existing, non-retired entities at edge write time.
   An edge to a retired entity is permitted only if explicitly flagged with
   `references_retired_entity: true` (for historical relationship modeling).
2. The universal base predicate vocabulary must be declared and enforced; unrecognized
   predicates are rejected. Base vocabulary: `ally_of`, `enemy_of`, `member_of`,
   `parent_of`, `child_of`, `located_in`, `owns`, `created`, `killed_by`, `succeeded_by`,
   `preceded_by`, `associated_with`. Game-specific extensions are registered in the
   naming-registry's `relationship_vocabulary`.
3. Self-referential edges (subject = object) are rejected for predicates that are
   logically reflexive and meaningless (e.g. `killed_by` self). Allowed for certain
   predicates (e.g. `preceded_by` may be used in time-loop narratives with
   `ambiguity_flag: true`).
4. Duplicate edges (same subject, predicate, object with no validity window distinction)
   are rejected with `DUPLICATE_RELATIONSHIP`.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Edge registration where `subject_entity_id` does not exist in the registry | Rejected: `DANGLING_ENTITY_REFERENCE`; error payload includes the unresolved ID |
| EC-002 | Edge registered with `valid_to_event_id` set to an event that precedes `valid_from_event_id` (inverted window) | Rejected: `INVALID_TEMPORAL_WINDOW` |
| EC-003 | Predicate not in the declared vocabulary | Rejected: `UNKNOWN_PREDICATE`; error suggests the most similar declared predicate |
| EC-004 | Relationship between two entities of logically incompatible types (e.g. `parent_of` between two `location` entities) | Accepted with a warning annotation: `TYPE_COMPATIBILITY_WARNING`; not blocked (worldbuilders may have intentional reasons for unusual relationships) |
| EC-005 | An edge's `valid_from_event_id` references a timeline event that does not exist | Rejected: `TIMELINE_EVENT_NOT_FOUND` |
| EC-006 | Loremaster marks a relationship as `canon_tier: ambiguous-by-design` (intentional ambiguity) | Accepted; the relationship is queryable but marked; contradiction checks skip this relationship for DI-007-style "correct by design" ambiguity |

## Canonical Test Vectors

| Input | Expected Output | Category |

| Edge `{subject: "kael", predicate: "member_of", object: "iron-guild", canon_tier: hard}` — both entities exist | Edge created; `edge_id` returned | happy-path |
| Edge where `subject_entity_id: "ghost-entity"` does not exist in registry | Error: `DANGLING_ENTITY_REFERENCE {unresolved: "ghost-entity"}` | error (EC-001) |
| Edge with `valid_from: event-100` and `valid_to: event-050` (reversed window) | Error: `INVALID_TEMPORAL_WINDOW` | error (EC-002) |
| Edge with unknown predicate `"befriends"` | Error: `UNKNOWN_PREDICATE`, suggestion: `ally_of` | error (EC-003) |

## Verification Properties

| VP | Property | Proof Method |
|----|----------|-------------|
| VP-1 | No edge in the relationship-graph has a `subject_entity_id` or `object_entity_id` that is absent from the entity-registry (no dangling references at rest) | CI continuity check: traverse all edges; for each, assert entity-registry lookup succeeds |
| VP-2 | For all edges with both `valid_from_event_id` and `valid_to_event_id` set, `valid_from.ordinal <= valid_to.ordinal` | Property-based test: generate random valid/invalid temporal windows; assert only valid ones accepted |
