# BC-12.12.001: Canon-KB Structure Initialization and Schema Validation

## Description

When a game production pipeline is initialized for a new `GameSpec`, the factory creates
a well-structured, versioned `canon-kb` artifact with all five mandatory subsystems
present: entity-registry, relationship-graph, timeline, naming-registry, and canon-facts.
The KB may be initially empty (no entries) but must have a valid, schema-conformant
structure. An empty-but-structurally-valid KB is valid; a missing subsystem is not.

## Preconditions

1. A `GameSpec` with a `game_id` exists and has been validated.
2. No `canon-kb` with the same `game_id` already exists in the artifact store
   (initialization is idempotent only on retry — it does not overwrite an existing KB).
3. The KB initialization is triggered by the factory pipeline (not directly by an agent)
   as part of game production setup.

## Postconditions

1. A `canon-kb` artifact is created at `.factory/specs/canon-kb/<game_id>/` containing
   all five mandatory subsystems as versioned, queryable files:
   - `entity-registry/`: empty registry, schema-valid. Schema requires: `entity_id`
     (stable, unique, content-addressable), `entity_type` (character | faction |
     location | item | event | concept), `canonical_name`, `status`, `provenance`,
     `canon_tier` (hard | soft | contested | ambiguous-by-design)
   - `relationship-graph/`: empty edge store, schema-valid. Schema requires: `edge_id`,
     `subject_entity_id`, `predicate` (typed relationship), `object_entity_id`,
     `canon_tier`, `valid_from_event_id`, `valid_to_event_id` (nullable)
   - `timeline/`: empty event store, schema-valid. Schema requires: `event_id`, `era`,
     `ordinal` (integer ordering within era), `summary`, `participating_entity_ids`
   - `naming-registry/`: empty registry with declared `phonotactic_rules` field
     (initially null; set when world-bible is seeded), `reserved_names: []`,
     `forbidden_names: []`, `canonical_spellings: {}`
   - `canon-facts/`: empty fact store. Schema requires: `fact_id`, `subject_entity_id`,
     `predicate`, `object`, `source_artifact_ref`, `canon_tier`, `valid_from_event_id`,
     `valid_to_event_id` (nullable), `ambiguity_flag` (boolean)
2. `canon-kb.metadata.version` is set to `"1.0"`, `game_id` is set, and
   `canon-kb.metadata.status` is `initialized`.
3. A `canon-kb-schema-validation` check runs immediately and passes, confirming the
   empty KB is structurally valid.

## Invariants

1. Every `entity_id` in the KB must be globally unique within the `game_id` scope for
   the lifetime of the KB. IDs are never reused after an entity is removed (append-only
   ID space).
2. The five subsystem directories must all be present; a KB missing any subsystem is
   structurally invalid and all reads/writes are rejected until the subsystem is repaired.
3. The `canon_tier` field on every entity, edge, and fact must be one of the declared
   values: `hard | soft | contested | ambiguous-by-design`. Unknown tiers are rejected
   at write time.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | `canon-kb` initialization attempted when one already exists for the `game_id` | Factory returns `CANON_KB_ALREADY_EXISTS`; no overwrite; existing KB untouched |
| EC-002 | GameSpec has no `game_id` set | Initialization rejected: `GAME_ID_REQUIRED`; KB not created |
| EC-003 | Initialization partially fails (e.g. entity-registry created but timeline fails to write) | Factory rolls back all created KB files; returns `CANON_KB_INIT_PARTIAL_FAILURE` with the failed subsystem identified; retry is safe |
| EC-004 | A second initialization call is made as a retry after a partial failure (EC-003) was cleaned up | Retry succeeds if the KB does not exist; treated as a fresh initialization |

## Canonical Test Vectors

| Input | Expected Output | Category |
|-------|----------------|----------|
| Valid `GameSpec{game_id: "pilot-roguelike"}`, no prior KB | `canon-kb` created at `.factory/specs/canon-kb/pilot-roguelike/` with all 5 subsystems, all empty, `metadata.status: initialized`, schema validation passes | happy-path |
| `GameSpec{game_id: "pilot-roguelike"}`, KB already exists | Error: `CANON_KB_ALREADY_EXISTS`; no write occurs | error (EC-001) |

## Verification Properties

| VP | Property | Proof Method |
|----|----------|-------------|
| VP-1 | Every initialized `canon-kb` passes schema validation immediately after creation with zero entries | Property-based test: initialize KB for any valid GameSpec; run schema validator; assert zero failures |
| VP-2 | All five subsystem directories exist after initialization; none may be absent | Property-based test: for all initialized KBs, assert directory existence of all five subsystems |
| VP-3 | Partial initialization failure results in complete rollback — no partial KB state persists | Integration test: simulate write failure at timeline; assert no files from the partially-initialized KB remain |
