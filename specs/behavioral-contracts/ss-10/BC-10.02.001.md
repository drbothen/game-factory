# BC-10.02.001: Compliance-Checklist Generated Per (Genre × Region) Profile

## Description

The factory generates a per-(genre × region) `compliance-checklist` that enumerates
every compliance obligation applicable to the game's declared genre profile and target
regions. Each item is classified as `GREEN` (machine-checkable CI gate), `YELLOW`
(factory flags, human decides), or `RED` (human-legal only). The checklist is the
compliance analog of `cert-preflight-checklist`. It drives the compliance dimension of
the 11-dimension convergence model. The factory owns the GREEN items as automated gates;
RED/YELLOW items are surfaced as human-gated tasks.

## Preconditions

1. A `game-profile` exists declaring:
   - `target_regions[]`: e.g., `["EU", "US", "DE", "AU", "JP", "KR"]`
   - `genre_profile`: e.g., `{monetization_model: premium|f2p|gacha, online: bool,
     child_directed_inputs: {art_style: <str>, subject_matter: <str>}, ...}`
   - `build_version`
2. A `ratings-submission-manifest` for the build version exists (BC-10.01.001).
3. The factory has a versioned `compliance-rule-set` for each (region, rule_category).
4. The `privacy-config-contract` for the build exists (BC-10.03.001).

## Behavior

1. For each `target_region` × applicable compliance domain:
   - Load the rule set for that (region, domain) combination.
   - For each rule, classify as GREEN/YELLOW/RED based on machine-checkability.
   - Evaluate GREEN rules immediately against available artifacts; emit PASS/FAIL.
   - For YELLOW rules: evaluate the detectable part; flag for human review.
   - For RED rules: emit `REQUIRES_HUMAN_REVIEW` with the specific legal question.

2. The standard GREEN items always evaluated:
   | Item | Mechanism |
   |------|---------|
   | PEGI-2026 minimum age prediction vs declared target audience | Rule engine over ratings-submission-manifest; flag conflict if target_audience_age < predicted_minimum |
   | Loot-box probability disclosure present (JP/CN/DE) | Check disclosure flag in economy graph |
   | Drop-table matches disclosed odds | Compare `disclosed_odds` vs `economy_graph.drop_rates`; within tolerance |
   | Spend-cap / playtime-limit / real-name gate configurable (CN) | Config presence check |
   | Kompu-gacha pattern absent (JP) | Structural pattern detection in economy graph |
   | Privacy policy present + structurally complete | Doc presence + section presence check |
   | Default high-privacy settings; geo/profiling off by default (UK Children's Code) | Config + privacy-config-contract check |
   | Age-gate + per-region digital-consent-age present | Flow presence + region config |
   | AI-disclosure manifest present and complete | Reference to BC-10.05.001 artifact |
   | Required legal-doc set present (EULA/ToS/privacy) | Doc presence check (BC-10.04.001) |
   | Accessibility feature tags present (subtitles, colorblind, remap) | Feature tag presence |

3. YELLOW items (factory flags, human decides):
   | Item | Flag condition |
   |------|---------------|
   | Germany §86a — candidate swastika/Nazi imagery detected in assets | Asset-content classifier detects candidate symbols → flag for human cultural review |
   | China-barred content categories — candidate content detected | Content tag matches CN-barred categories → flag |
   | Australia simulated gambling + real-money link | `simulated_gambling: true` AND `in_app_purchases: true` → flag for ACB/RC risk |
   | Regional sensitive content (Middle East, others) | Content tag flags → flag [UNVERIFIED per-country specifics] |

4. RED items (always human-legal):
   | Item | Human question |
   |------|---------------|
   | Loot box "is gambling" legal characterization (BE/NL/DE) | Is the paid-random mechanic gambling under applicable law? |
   | Child-directed determination ("is this game child-directed?") | Factory supplies inputs; human decides |
   | Lawful basis for GDPR data processing | Human-legal judgment |
   | DPIA reasoning adequacy | Human-legal judgment |
   | Legal-doc substantive sufficiency | Human-legal sign-off |

5. Emit `compliance-checklist` (JSON) with all items, their classifications, and evaluation results.

6. Update `convergence-report.dimensions.provenance_legal_compliance`:
   - `GREEN` iff all GREEN items PASS and all RED/YELLOW items have confirmed human sign-off
   - `AMBER` iff all GREEN items PASS but RED/YELLOW items pending human review
   - `BLOCKED` iff any GREEN item FAILS

## Postconditions

- `compliance-checklist` exists at `.factory/artifacts/compliance/<game_id>/compliance-checklist-<build_version>.json`.
- Every compliance item has a classification (GREEN/YELLOW/RED) and an evaluation result.
- No GREEN item is emitted as `REQUIRES_HUMAN_REVIEW`; no RED item is evaluated as PASS/FAIL by the factory.
- `convergence-report.dimensions.provenance_legal_compliance` is updated.

## Invariants

- INV-1: The factory NEVER asserts "this game is not gambling" for any jurisdiction.
  Loot-box gambling characterization is always RED.
- INV-2: The `child_directed_inputs` fields are supplied to the checklist; the "child-directed
  determination" question is always RED. The factory does not make this call.
- INV-3: The compliance rule set is versioned data, not hard-coded. Rule set must be
  re-validated per submission cycle (mirrors R-016 — fast-moving law).
- INV-4: PEGI-2026 interactive-risk rules are applied as of June 2026. The rule set is the
  canonical source; hard-coded values are forbidden.

## Edge Cases

| EC-ID | Scenario | Expected Result |
|-------|----------|----------------|
| EC-001 | Game targets China (CN region) | Checklist adds CN-specific items: banhao presence flag (human-required), playtime-limit config (GREEN), spend-cap config (GREEN), real-name gate (GREEN), NFT flag (RED if present); China content review (RED) |
| EC-002 | Game has `monetization_model: premium` (no IAP) | Loot-box/gambling items are N/A; only baseline items evaluated; checklist is shorter |
| EC-003 | PEGI-2026 predicted minimum age (18) conflicts with declared target_audience_age (13) | GREEN FAIL: "PEGI-2026 predicted minimum age 18 (NFT mechanic) conflicts with declared target_audience_age 13; must resolve before submission" |
| EC-004 | Compliance rule set for a target region not found | Warning: "No compliance rule set for region <X>; items for this region skipped"; checklist continues for other regions |
| EC-005 | Drop-table disclosed odds differ from economy graph by >5% | GREEN FAIL: "Disclosed drop rate for item <X>: 2.5%; actual: 4.1% (delta 1.6%, exceeds 0.1% tolerance)" |

## Canonical Test Vectors

| Game profile | Expected PEGI age conflict flag | Expected `kompu_gacha_absent` |
|-------------|--------------------------------|-------------------------------|
| Premium, single-player, no IAP, EU | None | N/A (not applicable) |
| F2P, `random_paid_items: true`, target_audience 12, EU | FAIL — predicted PEGI 16 vs audience 12 | PASS (if absent) |
| Gacha, JP target | N/A PEGI | PASS or FAIL per economy graph |
| Game with NFT, EU | FAIL — predicted PEGI 18 | N/A |

## Verification Properties

- VP-COMP-004: No loot-box gambling characterization item is evaluated as PASS or FAIL by the factory.
- VP-COMP-005: PEGI-2026 minimum age conflict is always a GREEN item evaluated automatically.
- VP-COMP-006: The compliance rule set version is recorded in the checklist artifact.
