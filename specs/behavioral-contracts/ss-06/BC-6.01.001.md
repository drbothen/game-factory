# BC-6.01.001: Economy Conservation Invariant

## Description

Verifies that the simulated game economy conserves declared resources across all
transactions. For any sequence of production, consumption, trade, or transfer
operations, the sum of a conserved resource across all tracked accounts must
equal the initial supply plus any declared faucet inputs minus any declared sink
outputs. This contract applies to every resource type in every game genre's
economy graph (gold, energy, action points, items, currency).

## Preconditions

1. A `simulation-bc` has been authored declaring the economy's resource types,
   initial supply amounts, and the set of faucet sources and sink destinations.
2. The game simulation code for the economy subsystem exists and is runnable
   headless (no GPU required).
3. The economy graph (`economy-graph` artifact) has been produced with all
   resource types, faucet flows, and sink flows declared.
4. The sim state is serializable: a snapshot of all account balances at any
   sim frame can be read as a deterministic value.
5. The TDD Red Gate is active for this simulation code (red-gate-state.json
   mode = strict on the economy-sim crate/module).

## Postconditions

1. For each conserved resource type R declared in the economy graph:
   `sum(balances(R, frame_N)) == initial_supply(R) + sum(faucet_inputs(R, 0..N)) - sum(sink_outputs(R, 0..N))`
   holds at every sampled frame N in the test run.
2. Any transaction that would violate conservation is rejected by the simulation
   with a machine-detectable error (assertion failure, panicking, or error return)
   — it is NOT silently accepted.
3. The test suite includes at least one property-based test that fuzzes over
   arbitrary valid transaction sequences and asserts the conservation invariant.
4. A conservation violation at any frame fails the sim/spec convergence dimension
   (BC-7.01.001) and is reported as a blocking defect.

## Invariants

1. The conservation invariant holds for ALL resources declared as conserved, not
   just the resources exercised in the happy-path test.
2. The invariant is verified over the serialized state, not over in-memory
   references — the serialized state is the authority (Filesystem-as-Memory principle).
3. Non-conserved resources (e.g., time-limited event tokens with expiry) must be
   explicitly declared as non-conserved in the economy graph; absence of declaration
   defaults to conserved.

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | Faucet generates resource and it is immediately consumed by a sink in the same frame | Conservation invariant still holds at frame boundary; net change equals faucet_in minus sink_out for that frame |
| EC-002 | Transaction sequence that attempts to spend more than available balance | Rejected before execution; balance unchanged; conservation invariant trivially holds |
| EC-003 | Simultaneous transactions from two different agents attempt to spend the same resource pool | At most one succeeds (atomicity); conservation holds; no double-spend |
| EC-004 | Economy graph is empty (no resource types declared) | Test vacuously passes; no assertion failures; system does not error |
| EC-005 | Resource declared as conserved but faucet/sink entries are missing from the economy graph | Build-time schema validation error; game-production-plan fails to advance past validation gate |
| EC-006 | Floating-point resource balances | Comparison uses declared epsilon tolerance (not bit-exact) for FP resources; integer resources use exact equality |
| EC-007 | Economy graph with 1000+ resource types | Property-based test covers a random subset each run; full exhaustive pass runs in nightly CI with extended timeout |

## Canonical Test Vectors

| Input | Expected Output | Category |
|-------|----------------|----------|
| Initial gold=100, two trades of +10 and -5 | Final gold=105; invariant holds; no error | happy-path |
| Initial gold=50, attempt spend of 60 | Transaction rejected; gold remains 50; invariant holds | error |
| Initial gold=100, 1000 random valid transactions generated by proptest | Conservation invariant holds for all 1000 frames; no violation | property-based |
| Initial energy=10, faucet adds 5 at frame 3, sink removes 8 at frame 7 | energy[0]=10, energy[3]=15, energy[7]=7; invariant holds at all frames | edge-case |
| Economy graph with no resource types | Test suite runs; 0 conservation assertions evaluated; pass | edge-case |
