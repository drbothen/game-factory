## Section 2.2 — Engine Adapter Conformance Gating (CAP-002)

**Overview.** Every engine adapter must pass the capability-gated conformance suite for
all of its declared capabilities before it may be used in factory production (DI-002,
ADR-0002). The suite is the anti-drift mechanism — without it, the four-seam adapter
pattern decays into engine-specific special cases. The conformance model is CRI/CSI-style:
adapters declare capability flags; the suite runs only tests for declared capabilities; an
adapter that claims a capability but fails its conformance test is not accepted at any
fidelity level.

The LSP-style capability negotiation (dynamic registration, `engineCapabilities` manifest)
is specified in CAP-001. CAP-002 builds on top of it by defining the acceptance gate:
conformance pass is required before the adapter is used.

## Section 2.3 — Determinism-Tier-Governed Replay Regression (CAP-003)

**Overview.** The factory records game input streams keyed by simulation frame, replays
them deterministically, and compares resulting simulation state against golden references.
The comparison method degrades by the engine adapter's declared determinism tier: T1
(`bitwise-cross-platform`) uses exact snapshot-hash diff; T2 (`same-machine`) uses snapshot
diff on a pinned CI runner; T3 (`tolerance-only`) uses a tolerance-window metric comparison.
An adapter declaring `replay: none` (no fixed-timestep or no RNG injection) causes the
regression dimension to degrade to human-playtest evidence.

The determinism tier is declared in the adapter manifest, conformance-verified (CAP-002),
and never assumed (DI-004). The replay-regression machinery also serves esports demo export
(same input stream, replay format) and anti-cheat evidence (server-authoritative state
comparison against recorded stream) when those genre-gated lanes are active (CAP-013).

## Cross-Capability Dependencies

| Dependency | Direction | Note |
|------------|-----------|------|
| CAP-001 → CAP-002 | CAP-002 depends on | Conformance runs on an adapter whose `engineCapabilities` manifest was negotiated by CAP-001. The manifest's declared capabilities are the input to CAP-002 test selection (BC-2.02.001). |
| CAP-001 → CAP-003 | CAP-003 depends on | The `replay` capability and `determinism_tier` field from the adapter manifest (CAP-001) are the preconditions for every CAP-003 BC. |
| CAP-002 → CAP-003 | CAP-003 depends on | CAP-002 conformance pass is a precondition for using an adapter in replay regression. An adapter whose `replay` capability failed conformance may not be used in CAP-003 workflows. |
| CAP-003 → CAP-013 (genre-gated) | CAP-003 enables | The same replay primitive serves esports demo export and anti-cheat spine (BC-3.03.009) when the competitive-multiplayer lane is active. |
| CAP-003 → CAP-006 | CAP-003 supports | Replay regression is a component of the 11-dimension convergence model tracked by CAP-007 under the `tests/replay` dimension. |
