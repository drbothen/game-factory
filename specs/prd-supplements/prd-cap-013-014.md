## 1. Capability Overview

### CAP-013 — Genre-Gated Optional Lane Activation (P2)

The factory activates genre-specific production lanes — competitive multiplayer /
esports, modding/UGC, monetization mechanics, and marketing/GTM — via genre profile
parameters without affecting the universal core. Inactive lanes produce no artifacts
and impose no constraints on the core pipeline.

**Tier:** 2 (v1-ready, genre-gated opt-in per AAA-RECONCILIATION §10).
**Default state:** ALL lanes OFF. The det-sim pilot ships with
`esports_enabled=false`, `modding_enabled=false`, and the marketing lane at
capture-recipe-only depth.

**Key invariant (load-bearing):** An inactive lane MUST produce zero artifacts and
impose zero constraints. A lane being "inactive" must be machine-verifiable — if the
artifact-output directory contains any lane-specific artifact when the lane is off, that
is a defect detectable by the conformance suite.

### CAP-014 — XR Platform Seam (P2, Tier 3 Deferred)

The factory provides the XR adapter seam — contract schema, capability definitions, and
fidelity model — so that an XR runtime can be added with zero core changes. The seam
uses OpenXR as its reference backend. Implementation is deferred until Unity/Godot
adapters are proven; only the seam contract and four schema artifacts are in scope.

**Tier:** 3 (seam reserved; implementation deferred per AAA-RECONCILIATION §10).
**Apple Vision Pro:** a separate, non-OpenXR target; modeled as its own adapter
target distinct from the OpenXR seam.

## 5. Out of Scope (explicitly excluded from these BCs)

### CAP-013 Exclusions

- Running live esports events, casting, prize disbursement, league operations (human-gated, out of autonomous scope)
- Live anti-cheat operations and kernel anti-cheat authoring (DI-010; wrap EAC/EOS only)
- EOMM-style engagement optimization as an autonomous objective (R-010 dark-pattern risk; objective is a human/product decision)
- In-game creation editors at UEFN/Roblox polish level (deferred past v1)
- Paid UGC / Marketplace monetization without human copyright-vetting gate (DMCA safe-harbor risk)
- Monetization-mechanics lane BCs in this batch (monetization-mechanics is a separate parallel batch under CAP-011)

### CAP-014 Exclusions

- XR runtime implementation (deferred; seam-only in v1)
- Bevy XR adapter (community-only experimental crate; no 1.0; must wait for Unity/Godot adapter proof)
- Headless comfort/nausea certification (physiologically impossible without a physical headset)
- Phone AR (ARKit/ARCore) — separate non-OpenXR sub-seam; deferred further than VR
- XR interaction spec BCs (interaction design; deferred to architect / UX designer scope)

## 7. Accepted Ambiguities and Resolutions

| Ambiguity | Resolution |
|-----------|-----------|
| Which rating models to support in ranking-system-contract? | Declare rating model as a typed enum: `elo \| glicko \| glicko2 \| trueskill \| trueskill2 \| weng_lin \| custom`. BC-13.02.001 covers the invariant set that applies to all models. |
| Should matchmaking-fairness-invariants cover EOMM-style engagement policy? | No. The EOMM *policy* (engagement vs fairness objective) is a declared human/product parameter, not a machine-verifiable invariant. BC-13.02.002 verifies structural correctness only (MWPM validity, no double-booking, symmetric weights). |
| Glicko-2 corrected Step-5 — which version to target? | The 2012-02-22 corrected iterative procedure (with 2022-03-22 item-4(b) revision `< → <=`). BC-13.02.001 pins this as a conformance vector. |
| mod.io vs Steam Workshop — default? | mod.io is the engine-agnostic, console-grade reference adapter. Steam Workshop is a Steam-only secondary adapter. BC-13.03.004 covers the mod.io reference; Workshop is a declare-and-degrade fallback. |
| Store asset specs — which platforms? | Steam (primary, WebFetch-verified against partner.steamgames.com), Apple App Store (developer.apple.com), and Google Play (support.google.com). Console and Xbox store specs are NDA-gated; flagged as `human-gated` in BC-13.04.001. |
| OpenXR version to target for XR seam? | OpenXR 1.1 (current as of June 2026, Khronos-verified). Loader/runtime architecture; Conformant Products directory wraps CTS. |
| Apple Vision Pro — OpenXR or separate? | Separate non-OpenXR target (`backend: visionos`). BC-14.02.003 enforces this hard split. |
| XR fidelity model — how to grade extensions? | Three tiers: `full` (OpenXR core or `XR_KHR_*`), `partial` (multi-vendor `XR_EXT_*` or vendor `XR_FB_*/XR_MSFT_*`), `none`. `comfort_certify` always maps to `human-gated`. BC-14.01.002 enforces the mapping. |
