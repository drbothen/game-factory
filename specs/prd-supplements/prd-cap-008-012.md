# PRD Supplement — CAP-008 and CAP-012: Playtest Protocol and Canon KB Grounding

> **Parallel-batch artifact.** This file covers CAP-008 (S=8) and CAP-012 (S=12) only.
> The master PRD index (`prd.md`) and BC-INDEX are produced in the integrate pass.
> BC IDs use S=8 for CAP-008 contracts and S=12 for CAP-012 contracts.

## 1. Capability Overviews

### CAP-008 — Structured Playtest Protocol (P1)

The factory runs structured human playtest sessions using the 3-lens convergence
protocol (say/do/behave), GEQ/PENS/SUS instruments, and produces a convergence report.
This is a mandatory human gate; the factory provides protocol scaffolding and evidence
recording but **never auto-scores fun or feel** (DI-007 is the absolute enforcement
invariant). The factory's role is to provide excellent structure so the human judgment
is well-informed — never to substitute for it.

**Grounding:** Brief §In Scope; RECONCILIATION §4 (Holdout → Playtest Protocol);
DI-007; `qa-testing-liveops.md §5` (3-lens model; GEQ/PENS/SUS discipline); PROC-005.

**Criticality: HIGH.** Playtest-satisfaction is one of 11 convergence dimensions;
its gate blocks release. An automated fun-score circumventing this gate is the
single most category-defining defect in the entire factory.

### CAP-012 — Canon Knowledge-Base Grounding (P1)

The factory maintains a Canon Knowledge-Base (entity-registry + relationship-graph +
timeline + naming-registry + canon-facts) with machine-checkable structural integrity.
All generative agents RAG over the Canon-KB before producing content. The Canon-KB
is described as "the sixth load-bearing seam" in the product brief (product-brief.md:111) —
architecturally equivalent to the engine adapter seams for the narrative domain.

**Grounding:** Brief §Overflow Context ("sixth load-bearing seam", product-brief.md:111); RECONCILIATION
§5.6a; `narrative-worldbuilding-lore.md §4` (verified structure); DI-012.

**Criticality: HIGH.** The Canon-KB is the single source of truth for all generative
narrative agents. Without it, parallel agent generation produces naming collisions,
timeline inconsistencies, and contradictory lore that cannot be corrected at scale.

## 3. Interface Definitions

### 3.1 CAP-008 Interface — Playtest Protocol Subsystem

**Trigger events (factory-internal)**

| Event | Description |
|-------|-------------|
| `milestone:playtest_reached` | Emitted when a playable build is archived at the playtest milestone. Triggers BC-8.08.001 (protocol scaffold generation). |
| `session:complete` | Emitted by the `playtest-evaluator` when all participants have finished. Triggers BC-8.08.003 (convergence report generation). |
| `signoff:submitted` | Emitted when a human reviewer submits the playtest sign-off form. Triggers BC-8.08.004 dimension update. |
| `artifact:write_attempted` | Continuously monitored by hook chain. Triggers BC-8.08.005 when matching fields are detected. |

**Artifact schemas (key fields)**

`playtest-protocol`:
```yaml
build_id_ref: <string>        # archived build ID
research_question: <string>
target_participant_count: <int>  # >= 5
recruitment_criteria:
  genre_familiarity_tier: <string>
  platform: <string>
session_tasks:
  - task_id: <string>
    description: <string>
    time_budget_minutes: <int>
instruments: [GEQ | PENS | SUS]   # at least one
think_aloud_type: concurrent | retrospective | both
convergence_thresholds:
  <instrument>_<subscale>_min: <float>
status: draft | approved
# FORBIDDEN FIELDS: fun_score, satisfaction_score, auto_verdict, predicted_satisfaction
```

`playtest-signoff-record`:
```yaml
reviewer_id: <string>           # human identity; must be in project human-reviewer allowlist
timestamp: <ISO-8601>
verdict: SATISFIED | NOT_SATISFIED | CONDITIONAL
conditions_for_satisfaction: <string>  # required if CONDITIONAL
human_verdicts_summary: <string>       # human-authored synthesis
report_ref: <artifact-ref>
protocol_ref: <artifact-ref>
```

## 4. Error Taxonomy

### CAP-008 Error Codes

| Code | Category | Severity | Description |
|------|----------|----------|-------------|
| `PLAYTEST_PROTOCOL_ALREADY_APPROVED` | Protocol lifecycle | Broken | Protocol with `status: approved` already exists for this milestone; no overwrite allowed |
| `BUILD_NOT_ARCHIVED` | Prerequisite | Broken | Playtest milestone reached but build has not been archived; cannot generate protocol |
| `BUILD_NOT_RUNNING` | Prerequisite | Broken | Session started but build is not running; session record not created |
| `SESSION_NOT_COMPLETE` | Workflow sequence | Broken | Convergence report requested before evaluator closed the session |
| `AGENT_SIGN_OFF_FORBIDDEN` | Security/integrity | Broken | An automated process attempted to create a `playtest-signoff-record`; this is a defect |
| `CONDITIONS_REQUIRED_FOR_CONDITIONAL_VERDICT` | Schema validation | Broken | `CONDITIONAL` verdict submitted without `conditions_for_satisfaction` field |
| `FUN_SCORE_EMISSION_FORBIDDEN` | DI-007 violation | Broken | Agent artifact contains a computed fun/satisfaction/auto-verdict field; write blocked |
| `DUPLICATE_PARTICIPANT_SUBMISSION` | Data integrity | Degraded | Same participant submitted instrument responses twice |
| `PLAYTEST_PROTOCOL_IN_PROGRESS` | Concurrency | Degraded | Protocol generation already in progress for this milestone |

## 6. Cross-Capability Dependencies

### CAP-012 grounds CAP-004 and CAP-005 generation (keystone dependency)

The Canon-KB grounding contract (BC-12.12.009) is explicitly cross-capability:

- **CAP-004 (Asset Generation):** Any agent generating an asset *described by name*
  (character model, named item, faction emblem) must retrieve the corresponding
  entity record and canonical facts from the Canon-KB before generation. This ensures
  visual descriptions are consistent with the world-bible (e.g., "Kael is described
  as having red hair in canon — the character model must reflect this").

- **CAP-005 (Multi-Discipline Production):** Every specialist agent in the
  Studio-of-Agents that produces text-bearing artifacts — quest-designer, bark-writer,
  codex-writer, copywriter, systemic-writer — is in the required-grounding list. The
  Canon-KB is the single source of truth that makes parallel 66-agent production
  coherent rather than contradictory.

The dependency is one-directional: CAP-012 grounds CAP-004 and CAP-005; CAP-004 and
CAP-005 do not modify the Canon-KB (they consume it read-only, with the exception that
their artifacts become `source_artifact_ref` inputs when the worldbuilder registers new
facts discovered during production).

### CAP-008 and CAP-012 do not directly depend on each other

These two capabilities are orthogonal in the production pipeline:

- CAP-008 (Playtest Protocol) operates on a running game build and player responses —
  it does not read or modify the Canon-KB.
- CAP-012 (Canon-KB) operates on narrative artifact production — it does not interact
  with the playtest protocol or session evidence.

However, both are governed by the same class of invariant: **the factory provides
structure; human judgment has a protected gate.** In CAP-008, the protected gate is
the playtest sign-off. In CAP-012, the protected gate is the loremaster's adjudication
of flagged continuity issues and retcon authorizations. Neither gate can be automated.

## 8. Ambiguities Resolved

The following design decisions were made during BC authoring where the L2 domain
spec was silent or ambiguous:

| # | Ambiguity | Resolution |
|---|-----------|-----------|
| 1 | L2 spec says "GEQ/PENS/SUS instruments" but does not specify minimum instrument count | Resolved: at minimum ONE instrument required; SUS is required if usability is a stated research concern; all three is the default if `playtest_instruments` is empty in the GenSpec |
| 2 | L2 spec does not specify the minimum participant count for a valid playtest | Resolved: minimum 5 participants per GUR discipline (qualitative research standard); factory clamps to 5 with a warning if derived count is lower |
| 3 | L2 spec does not define what counts as a "fun-score field" vs a legitimate proxy metric | Resolved: the detection ruleset distinguishes computed experiential verdicts (blocked) from proxy observational metrics such as `frustration_signal` (permitted). The field naming conventions in BC-8.08.005 are the operative definition |
| 4 | L2 spec says Canon-KB has "entity-registry + relationship-graph + timeline + naming-registry + canon-facts" but does not specify if any may be omitted | Resolved: all five subsystems are mandatory and must be present in an initialized KB; a missing subsystem is a structural defect |
| 5 | L2 spec does not specify how naming collision detection handles diacritics | Resolved: case-insensitive and diacritic-normalized by default; diacritic policy may be explicitly overridden in the game's naming-registry config |
| 6 | L2 spec says agents "RAG over Canon-KB" but does not specify retrieval shape (vector vs. graph) | Resolved: graph-shaped retrieval (entity-neighborhood subgraph) is required, not purely vector-similarity. This is grounded in `narrative-worldbuilding-lore.md §4.4` citing KG-based fact verification literature showing graph retrieval outperforms flat-document RAG for fact-consistency |
| 7 | L2 spec is silent on what happens to narrative artifacts when a retcon occurs | Resolved: affected artifacts enter `retcon-pending` state; factory does NOT auto-update content; loremaster must individually clear each (BC-12.12.008) |
| 8 | L2 spec does not address bootstrap case (empty Canon-KB at first generation) | Resolved: empty KB is valid bootstrap state; artifacts produced against empty KB are tagged `ungrounded_bootstrap: true`; loremaster must ratify before any bootstrap artifact becomes a canon-fact source |
